# گزارش معاملات در تلگرام

این سرویس معاملات شاهین، موج‌سوار و ققنوس را از دیتابیس‌های همان اجرا می‌خواند. نیاز به کلید صرافی یا پورت ورودی ندارد. دستورات `/open`، `/closed` و `/status` و دکمه‌های فارسی در چت خصوصی در دسترس‌اند. هر صفحه پنج ردیف دارد؛ برای ادامه `/closed 2` یا `/open 2` بفرستید.

معاملات باز: نام ربات، نماد، جهت، قیمت ورود، حجم، حد ضرر، هدف اول شاهین و زمان سیگنال. سفارش معلق پوزیشن باز محسوب نمی‌شود. تاریخچه: قیمت ورود و خروج، حجم خروج، سود/زیان خالص ثبت‌شده، زمان خروج و دلیل. خروج جزئی شاهین هم یک ردیف جدا دارد؛ تعداد خروج‌ها لزوماً تعداد معاملات کامل نیست. سود لحظه‌ای از قیمت بازار محاسبه نمی‌شود. زمان‌ها UTC هستند. این سرویس دادهٔ اجرای paper موجود را نمایش می‌دهد و معامله ایجاد یا اجرا نمی‌کند.

## راه‌اندازی با Docker Compose

۱. در تلگرام با `@BotFather` و دستور `/newbot` یک ربات بسازید.
۲. در فایل `.env` کنار `telegram-compose.yml` این دو مقدار را قرار دهید:

```dotenv
TELEGRAM_BOT_TOKEN=توکن_دریافتی_از_BotFather
TELEGRAM_ALLOWED_USER_IDS=123456789
TELEGRAM_RUNTIME_DIR=/absolute/path/to/existing/lbank_project/runtime
```

شناسه، عدد حساب شخصی تلگرام است؛ نام کاربری یا شماره تلفن نیست. برای چند حساب، شناسه‌ها را با کاما جدا کنید. فقط این افراد و فقط در چت خصوصی پاسخ می‌گیرند. برای یافتن شناسه می‌توانید به `@userinfobot` پیام بدهید. توکن را در کد یا Git ثبت نکنید.

۳. در پوشهٔ `lbank_project` روی سروری که ربات‌های معاملاتی در حال اجرا هستند:

```bash
docker compose -p trade-telegram -f telegram-compose.yml up -d --build --no-deps telegram
docker compose -p trade-telegram -f telegram-compose.yml logs --tail=50 telegram
```

سرویس از همان پوشهٔ `runtime` و سه دیتابیس استفاده می‌کند. اگر ربات‌های معاملاتی هنوز اجرا نشده‌اند، آن‌ها را طبق راهنمای اصلی راه‌اندازی کنید؛ سرویس تلگرام به‌تنهایی داده تولید نمی‌کند. در چت ربات تازه‌ساخته‌شده `/start` بفرستید.

## نصب در زمان بازبودن معاملات

تلگرام Dockerfile و فایل Compose مستقل دارد. دستور بالا فقط پروژهٔ `trade-telegram` را اجرا می‌کند؛ هیچ سرویس معاملاتی در این فایل تعریف نشده و Dockerfile و Compose اصلی تغییر نمی‌کنند. موتور، تنظیمات استراتژی، حجم، SL/TP و طرح دیتابیس با این تغییر به‌روزرسانی نمی‌شوند.

پیش از نصب، مسیر واقعی دیتابیس‌های اجرای فعلی را پیدا کنید؛ اگر اجرا با Python یا customer-compose است، ممکن است مسیر `data/` یا پوشهٔ مشتری باشد. `TELEGRAM_RUNTIME_DIR` باید همان پوشهٔ موجود باشد. پوشهٔ جدید نسازید و فایل‌های runtime یا config را با نسخهٔ مخزن جایگزین نکنید. مسیر غایب عمداً باعث خطای شروع می‌شود.

برای این نصب از `docker compose down`، `restart` یا `up --build` روی پروژهٔ معاملاتی استفاده نکنید. فایل‌های تلگرام را می‌توانید در پوشه‌ای جدا قرار دهید و مسیر پوشهٔ فعلی داده را به آن بدهید؛ نیازی به pull یا جابه‌جایی کد زیر پردازش فعال نیست. فقط `telegram_bot.py`، `Dockerfile.telegram` و `telegram-compose.yml` به همراه `.env` مخصوص تلگرام لازم‌اند.

پوشهٔ داده داخل کانتینر تلگرام هم فقط‌خواندنی است و این سرویس کلید صرافی دریافت نمی‌کند. برای SQLite در حالت WAL، کل پوشه (شامل فایل‌های `-wal` و `-shm`) باید قابل خواندن باشد. اگر SQLite اجازهٔ خواندن نداد، گزارش هشدار می‌دهد؛ مجوز نوشتن ندهید و از `immutable=1` برای دورزدن WAL استفاده نکنید.

پیش از هر به‌روزرسانی اصلی، از دیتابیس‌های موجود با SQLite Online Backup (`Connection.backup`) نسخهٔ پشتیبان بگیرید؛ کپی فایل `.db` به‌تنهایی هنگام اجرای WAL پشتیبان قابل اتکا نیست. این نسخهٔ کد شامل دیتابیس اجرای شما نیست. نصب گزارش‌گیر جایگزین بررسی سلامت موتور فعلی نیست.

پس از نصب، تعداد و نماد پوزیشن‌ها و SL/TP را با داشبورد فعلی مقایسه کنید. موتور باید همان پردازش/کانتینر قبلی بماند. برای حذف گزارش‌گیر، فقط این پروژه را متوقف کنید:

```bash
docker compose -p trade-telegram -f telegram-compose.yml down
```

این دستور به پروژهٔ معاملاتی مربوط نیست و bind mount داده را حذف نمی‌کند. نصب روی سرور واقعی هنوز از این محیط انجام نشده است.

## اجرای مستقیم با پایتون

وابستگی اضافه‌ای لازم نیست (Python 3.10+). این برنامه فایل `.env` را خودکار بارگذاری نمی‌کند؛ متغیرها را در تنظیمات سرویس یا محیط شل قرار دهید. در اجرای مستقیم مسیرهای پیش‌فرض `data/` کنار فایل برنامه هستند. برای گزارش اجرای Compose یا دیتابیس‌های سفارشی، هر سه مسیر را صریح تنظیم کنید:

```bash
cd lbank_project
export BOT_DB="$PWD/runtime/lbank_ichimoku_bot.db"
export C3_DB="$PWD/runtime/c3_sleeve.db"
export PA_DB="$PWD/runtime/pa_sleeve.db"
# TELEGRAM_BOT_TOKEN و TELEGRAM_ALLOWED_USER_IDS را در محیط سرویس تنظیم کنید.
python telegram_bot.py
```

برای هر توکن فقط یک نمونه اجرا کنید. این سرویس از long polling استفاده می‌کند؛ اگر توکن قبلاً webhook داشته، ابتدا webhook آن را از طریق Telegram Bot API حذف کنید. خطای 409 می‌تواند نشان‌دهندهٔ webhook یا نمونهٔ هم‌زمان دیگر باشد. خطای 401/404 یعنی توکن را بررسی کنید.

دیتابیس‌ها با اتصال SQL فقط‌خواندنی باز می‌شوند. دیتابیس غایب یا قفل‌شده هشدار گزارش ناقص می‌دهد؛ فایل خالی ساخته نمی‌شود. این گزارش وضعیت روشن‌بودن ربات معاملاتی را تضمین نمی‌کند؛ اگر موتور متوقف شود، آخرین دادهٔ ذخیره‌شده همچنان قابل مشاهده است. با ری‌استارت سرویس تلگرام ممکن است پیام‌های تحویل‌نشدهٔ قبلی دوباره پاسخ بگیرند. اعلان خودکار ورود/خروج در این نسخه وجود ندارد؛ اطلاعات با انتخاب منو یا ارسال دستور تازه خوانده می‌شوند.
