# ثبت‌نام و دو نوع اشتراک

کاربران از `/register/` با نام کاربری، رمز و تکرار رمز حساب می‌سازند و بلافاصله
با نشست HttpOnly وارد پنل می‌شوند. ثبت‌نام رایگان است و خودبه‌خود لایسنس یا
مجوز معامله نمی‌دهد. رمز حداقل ۱۲ کاراکتر است، با scrypt ذخیره می‌شود و در
خروجی API، گزارش یا مرورگرِ ذخیره‌شده قرار نمی‌گیرد. ثبت‌نام محدودیت نرخ دارد.
ایمیل و بازیابی خودکار رمز در این نسخه وجود ندارد؛ فرمان مدیریتی reset-password
قبلی همچنان در دسترس است.

## انتخاب سرویس

| سرویس | دسترسی | حساب صرافی |
|---|---|---|
| فقط سیگنال (`signals`) | نمایش پیشنهاد ورود، حد ضرر، هدف اول در صورت تعریف، زمان و اعتبار سیگنال | لازم نیست؛ هیچ مجوز ورود یا افزایش پوزیشن ندارد |
| معاملهٔ خودکار (`autotrade`) | سیگنال‌ها و مجوز ورود/مدیریت ربات، طبق لایسنس سرمایه‌ای | برای فعال‌سازی، شناسه و سرمایهٔ حساب باید توسط مدیر بررسی شوند |

**موتور معاملات فعلی همچنان paper است؛ انتخاب یا خرید محصول معاملهٔ خودکار،
ارسال سفارش واقعی به صرافی را فعال نمی‌کند.** این موضوع در کارت انتخاب محصول
و وضعیت اجرای ربات به مشتری نشان داده می‌شود. سفارش واقعی نیازمند اتصال اجرایی
کامل و تأییدشدهٔ صرافی است.

لایسنس، نام محصول را در بخش امضاشدهٔ Ed25519 نگه می‌دارد. تغییر محصول در
مرورگر یا ویرایش فایل به معنی افزایش دسترسی نیست. همهٔ مسیرهای ورود شاهین،
موج‌سوار و ققنوس، لایسنس فقط سیگنال را رد می‌کنند؛ استاپ و خروج پوزیشن‌های
ازقبل‌موجود ادامه دارد. لایسنس‌های قدیمی بدون فیلد محصول با رفتار قبلی autotrade
خوانده می‌شوند. نصب فایل سیگنال در توزیع معامله‌گر مجاز نیست؛ سیگنال از پنل
مرکزی تحویل داده می‌شود.

در حال حاضر هر مشتری یک اشتراک فعال دارد. تغییر signals به autotrade در میان
دوره با همان مدت، حفظ انقضا، سقف کمترنشده و مابه‌التفاوت مثبت ممکن است. اعتبار
قیمت پلن قبلی از مبلغ کامل ثبت‌شده در لایسنس خوانده می‌شود، نه قیمت جدید؛
تعرفهٔ تازه نمی‌تواند اعتبار پرداخت قبلی را کم کند. تغییر معکوس یا پلن ارزان‌تر
پس از انقضا انجام می‌شود. تمدید بر اساس قواعد سرمایه‌ای قبلی است.
برای سیگنال، سقف سرمایه، بازهٔ سرمایهٔ هدفِ انتخابی مشتری است و به کلید صرافی
یا ثبت واریز و برداشت متصل نیست.

## قیمت‌ها و بسته‌بودن فروش

طبق تصمیم مالک، **فروش هر دو محصول به‌صورت پیش‌فرض بسته است و قیمت نهایی
برای هیچ‌کدام تنظیم نشده است.** تعرفه‌های قبلی یا اعداد تست، خودکار قیمت
نهایی محصولات نمی‌شوند. ثبت سفارش و تأیید/صدور آن تا تعیین و بازکردن صریح
فروش در سمت سرور رد می‌شوند. بستن فروش، اشتراک‌های پرداخت‌شده را باطل نمی‌کند.

قیمت‌ها برای دو محصول مستقل، در پایگاه دادهٔ پنل و بر حسب سنت صحیح ذخیره می‌شوند.
فایل ورودی مدیر، دلار است. ابتدا از `pricing/template.json` کپی بگیرید و همهٔ
مقادیر null را با قیمت‌های نهایی مثبت برای هفت سقف و سه مدت جایگزین کنید.
فایل ناقص، مقدار صفر، منفی یا غیرعددی رد می‌شود و فروش را باز نمی‌کند.

از پوشهٔ `lbank_project` و با همان تنظیمات DB و PORTAL_KEY_FILE پنل:

```bash
python portal_admin.py pricing-status
# ذخیرهٔ قیمت پیشنهادی، بدون بازکردن فروش:
python portal_admin.py configure-pricing signals --file pricing/signals.final.json
python portal_admin.py configure-pricing autotrade --file pricing/autotrade.final.json
```

**فقط پس از تصمیم نهایی مالک**، فرمان configure-pricing را برای محصول موردنظر
با `--enable-sales` اجرا کنید. این گزینه در راه‌اندازی عادی، بیلد یا مهاجرت اجرا
نمی‌شود. این تغییر کد، هیچ قیمت تولیدی یا فروش فعالی در محیط ایجاد نکرده است.
بستن فوری فروش:

```bash
python portal_admin.py close-sales signals
python portal_admin.py close-sales autotrade
```

تغییر تعرفه نسخهٔ جدید می‌سازد. سفارش در انتظار با نسخهٔ قدیمی باید لغو و با
تعرفهٔ تازه دوباره ثبت شود؛ مدیر نمی‌تواند قیمت متفاوت را روی همان درخواست
تأیید کند. داده‌های schema=4 به schema=5 مهاجرت می‌کنند؛ سفارش‌های قبلی
برچسب autotrade می‌گیرند و فروش پس از مهاجرت همچنان بسته می‌ماند.

پس از نهایی‌شدن قیمت و ثبت سفارش، پرداخت فعلاً خارج از پنل بررسی می‌شود.
برای تأیید signals فقط شناسهٔ سفارش، کلید صادرکننده و رسید لازم است:

```bash
python portal_admin.py approve-license ORDER_ID \
  --private-key issuer-keys/license.private.pem --payment-ref RECEIPT_ID
```

برای autotrade، `--account-id exchange:uid` و `--equity-usd AMOUNT` هم لازم است؛
سپس فایل معتبر باید روی نصب همان مشتری اعمال شود. جزئیات در
[CAPITAL_LICENSE_FA.md](CAPITAL_LICENSE_FA.md) است.

## منبع و تحویل سیگنال

تحویل در این نسخه **داخل پنل وب** است، نه Telegram، ایمیل یا push.
پنل دارای اشتراک معتبر هر ۳۰ ثانیه `/api/me/signals` را می‌خواند. اشتراک
منقضی یا کاربر بدون لایسنس به این API دسترسی ندارد. عبور سرمایهٔ autotrade
از سقف فقط ورود جدید را متوقف می‌کند؛ سیگنال تا پایان اعتبار زمانی در دسترس است.

سیگنال‌ها از outbox محلی اسکنرهای همان سه استراتژی می‌آیند. برای یک runtime
اختصاصیِ تولید سیگنال با دادهٔ واقعی کندل:

```bash
export PAPER_DATA_MODE=csv-lbank
export BOT_SIGNAL_FEED_ENABLED=1
export BOT_SIGNAL_FEED_DB=/absolute/path/to/signal-runtime/signal_feed.db
```

از همان runtime معمول ربات اجرا کنید؛ مسیر BOT_DB و سایر مسیرها باید به نصب
اختصاصی تولیدکننده اشاره کنند. برای تولید بدون ورود، auto_trade_enabled شاهین
و enabled دو ربات دیگر را در **runtime اختصاصی تولیدکننده** خاموش نگه دارید.
با فعال‌بودن انتشار، اسکنرها می‌توانند setup ثبت کنند ولی تنظیم خاموش یا لایسنس
سیگنال، اجازهٔ ورود ایجاد نمی‌کند. این تغییر تنظیمات runtime فعلی شما را عوض نکرده است.

در سرویس پنل:

```bash
export PORTAL_SIGNAL_FEED_DB=/absolute/path/to/signal-runtime/signal_feed.db
```

در Docker پوشهٔ حاوی feed و WAL آن را از تولیدکننده به پنل **read-only** mount
کنید و همین متغیر را به مسیر داخل کانتینر بدهید. در Composeهای پنل متغیر مسیر
اختیاری پذیرفته می‌شود ولی هیچ مسیر مشتری خودکار mount نشده است.
کلیدهای صرافی یا کلید خصوصی لایسنس در خروجی سیگنال قرار نمی‌گیرند.

انتشار به‌صورت پیش‌فرض خاموش است؛ دادهٔ `demo` یا حالت ناشناخته هرگز در feed
مشتریان منتشر نمی‌شود. دیتای csv باید به‌روز و از مسیر معتبر فعلی کندل‌های
فیوچرز باشد. اسکنر برای نمایش سیگنال هیچ سفارش یا پوزیشن جدیدی ایجاد نمی‌کند.
API فقط جدول outbox عمومیِ انتخاب‌شده توسط مدیر را می‌خواند، نه دیتابیس پوزیشن
یا موجودی یک مشتری دیگر. سیگنال‌های تکراری همان کندل یک‌بار ثبت می‌شوند.

setup با اجرای واقعی تفاوت دارد. سطوح، قیمت تضمین‌شدهٔ fill نیستند؛ تأیید شکست،
شرایط بازار و تصمیم مشتری همچنان مهم‌اند. سیگنال شاهین حداکثر تا کندل بعدی
یا مهلت کوتاه‌تر سفارش اعتبار دارد. موج‌سوار و ققنوس نیز تا بسته‌شدن کندل بعدی
اعتبار دارند. سیگنال منقضی به‌وضوح برچسب می‌خورد. هدف ثابت برای استراتژی دارای
trailing ساخته نمی‌شود. بدون منبع، پنل پیام عدم راه‌اندازی نشان می‌دهد؛ هیچ
نمونهٔ تصادفی یا دادهٔ مصنوعی برای پرکردن صفحه تولید نمی‌شود.

## اجرا و تست

```bash
npm --prefix frontend ci
npm --prefix frontend run build
PYTHONPATH=. python -m pytest tests/test_signup_products.py tests/test_portal_browser.py -q
```

تست‌ها از پایگاه داده، کلید و تعرفهٔ موقت جدا استفاده می‌کنند. هیچ قیمت تجاری
با اجرای تست تنظیم نمی‌شود. آزمون‌ها ثبت‌نام، رقابت نام کاربری، بسته‌بودن فروش،
قیمت مستقل، تغییر نسخه، جلوگیری از معامله با لایسنس سیگنال، انتشار سه اسکنر
بدون پوزیشن، منع دیتای demo و مرورگر موبایل را بررسی می‌کنند.
