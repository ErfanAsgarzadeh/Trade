# تحویل Trade به چند مشتری

## معماری این نسخه

برای هر مشتری یک نصب مستقل Docker Compose با نام، پورت، شبکه، رمز،
تنظیمات، سه دیتابیس و پوشه‌های داده جدا ایجاد می‌شود. سه ربات درون همان نصب
سرمایه مشترک دارند؛ سرمایه مشتریان با هم ترکیب نمی‌شود.
این نسخه سامانه SaaS با ثبت‌نام و پنل مدیریت مشترک نیست. مشتری می‌تواند روی
سیستم خودش اجرا کند یا مدیر چند نصب را روی یک سرور کنترل‌شده نگه دارد.
در میزبانی مشترک، به مشتری دسترسی shell یا Docker socket سرور ندهید.

کد هنوز paper-only است. آماده‌سازی چند مشتری، پشتیبانی معامله واقعی LBank
را اضافه نمی‌کند؛ اعتبارسنجی dry_run_mode=false همچنان آن را رد می‌کند.

## ساخت کلید فروشنده

از پوشه `lbank_project` و پس از نصب `requirements.txt` اجرا کنید:

```bash
python customer_manager.py keygen --private-key issuer-keys/issuer.private.pem --public-key issuer-keys/issuer.public.pem
```

کلید خصوصی فقط نزد فروشنده بماند. از آن پشتیبان امن بگیرید؛ داخل بسته مشتری
یا Git قرار نگیرد. فایل‌های مشتری، کلیدها و releases در `.gitignore` مستثنا هستند.
ابزار فایل‌های کلید موجود را بازنویسی نمی‌کند.

## ایجاد دو مشتری

```bash
python customer_manager.py create alice --private-key issuer-keys/issuer.private.pem --public-key issuer-keys/issuer.public.pem --port 8101 --paper-capital 1000 --days 30 --plan starter
python customer_manager.py create bob --private-key issuer-keys/issuer.private.pem --public-key issuer-keys/issuer.public.pem --port 8102 --paper-capital 5000 --days 90 --plan professional
```

شناسه باید انگلیسی کوچک، ۲ تا ۴۰ کاراکتر و شامل حرف/عدد/خط‌تیره باشد.
هر مشتری رمز تصادفی ۳۲کاراکتری مستقل می‌گیرد. مسیر مشتری موجود بازنویسی نمی‌شود؛
پورت تکراری در مجموعه مشتریان رد می‌شود. اشغال پورت توسط برنامه دیگر ممکن است
در زمان Docker خطا بدهد. سرمایه در این نسخه فقط سرمایه اولیه paper است.

نام plan برچسب قرارداد است؛ صورتحساب، پرداخت، قیمت‌گذاری سرمایه و محدودیت
سرمایه واقعی در این نسخه خودکار نشده‌اند.

## تحویل بسته اولیه

```bash
python customer_manager.py export alice --output releases/trade-alice.zip
python customer_manager.py export bob --output releases/trade-bob.zip
```

بسته با allowlist ساخته می‌شود؛ هیچ دیتابیس، آرشیو بازار، کلید خصوصی صادرکننده
یا فایل اضافه از محیط فروشنده وارد آن نمی‌شود. بسته شامل رمز همان مشتری است؛
آن را فقط از مسیر خصوصی به همان مشتری بدهید. خروجی موجود بازنویسی نمی‌شود.
از نصب فعال، بسته اولیه صادر نمی‌شود تا مشتری جدید پوزیشن یا موجودی قبلی نگیرد.

برای اجرای میزبانی‌شده:

```bash
cd customers/alice
docker compose up -d --build
```

برای مشتری دیگر از پوشه خودش اجرا کنید. ابزار ورود مشتری را به محیط پردازش
می‌بندد؛ client درخواست HTTP نمی‌تواند شناسه مشتری یا مسیر دیتابیس را انتخاب کند.
شناسه مالک runtime نیز هنگام شروع ثبت/بررسی می‌شود و اتصال اشتباهی نصب دیگر را رد می‌کند.

## تمدید زمان‌دار

```bash
python customer_manager.py renew alice --private-key issuer-keys/issuer.private.pem --days 90 --plan starter
```

اعتبار جدید از زمان صدور آغاز می‌شود؛ این فرمان تعداد روز را از انتهای اعتبار قبلی
اضافه نمی‌کند. مقدار درست را مطابق قرارداد تعیین کنید. فقط فایل امضاشده عوض
می‌شود؛ دیتابیس، رمز، سرمایه و تنظیمات باقی می‌مانند. جایگزینی فایل در پوشه
license روی نصب مشتری برای تمدید کافی است. پوشه به‌صورت read-only در کانتینر
mount می‌شود تا تغییر اتمیک فایل از میزبان قابل مشاهده باشد.

با انقضا، نامعتبرشدن امضا یا ناسازگاری شناسه مشتری، ورودها و افزودن‌ها بسته
می‌شوند. مدیریت پوزیشن‌ها، خروج، احراز هویت و داشبورد ادامه می‌یابند.
لایسنس Ed25519 است؛ دستکاری تاریخ بدون کلید خصوصی امضا را نامعتبر می‌کند.

## امنیت و حدود لایسنس

رمز پیش‌فرض 1234 حذف شده است. اجرای واقعی سرور داشبورد رمز حداقل ۱۶ کاراکتر
می‌خواهد؛ راز فایل در HTTP یا گزارش وضعیت بازگردانده نمی‌شود. احراز هویت API
و محدودیت تلاش ناموفق وجود دارد. ده شکست در ۶۰ ثانیه، همان client را موقتاً
متوقف می‌کند؛ پشت پراکسی ممکن است مشتریان یک IP مشترک دیده شوند.

پورت‌ها روی loopback هستند. برای SaaS اینترنتی، HTTPS، احراز هویت مناسب کاربران،
مانیتورینگ، محدودیت منابع و پشتیبان‌گیری مستقل لازم است؛ این‌ها با ساخت بسته
خودکار ایجاد نشده‌اند. کانتینرها runtime مشتری دیگر و کلید صادرکننده را mount نمی‌کنند.

لایسنس محلی DRM شکست‌ناپذیر نیست: کسی که کد/محیط اجرا را کنترل می‌کند ممکن است
guard را حذف کند، ساعت را عقب ببرد یا بسته خودش را کپی کند. مخزن عمومی فعلی
نیز محرمانگی کد ایجاد نمی‌کند. این نسخه امضا/انقضا/جداسازی را فراهم می‌کند؛
کنترل دستگاه، ابطال آنلاین و سامانه پرداخت پیاده‌سازی نشده‌اند.
برای اجرای مدیریتی، متغیرهای لایسنس را فقط مدیر تنظیم کند. اجرای توسعهٔ قدیمی
بدون متغیر لایسنس برای سازگاری باز است؛ customer_entrypoint الزام را روشن می‌کند.

## تست و ارتقا

```bash
python -m pip install -r requirements-dev.txt
python -m pytest tests -q
```

در ارتقا، source نصب هر مشتری باید به‌روزرسانی و image دوباره build شود؛ runtime
حفظ شود. دستور create برای upgrade یا restore نیست. از runtime نصب‌های فعال
با توقف سرویس‌ها پشتیبان سازگار بگیرید. پیش از فعال‌سازی نسخه جدید، وضعیت
پوزیشن‌های هر سه ربات را کنترل کنید.

## نتیجهٔ اعتبارسنجی این تغییر

در ۲۰۲۶-۱۰-۱۳ مجموعهٔ تست‌ها با ۳۱۸ تست موفق و ۱۰ تست skipped اجرا شد.
تست‌های جدید شامل اجرای هم‌زمان دو نصب واقعی Python/Uvicorn با سرمایهٔ
۱۰۰۰ و ۲۰۰۰، رد رمز مشتری دیگر، استقلال تنظیمات و ایجاد سه دیتابیس مستقل
برای هر مشتری هستند. انقضای لایسنس، رد امضای دستکاری‌شده، حفظ داده هنگام
تمدید و ادامهٔ خروج پوزیشن‌های هر سه ربات نیز آزمایش شد.
وابستگی‌های اصلی با نسخه‌های قفل‌شده اجرا شدند؛ بررسی syntax جاوااسکریپت
داشبورد و git diff --check نیز موفق بود. Docker در محیط ارزیابی نصب نبود؛
ساخت image و اجرای واقعی Compose هنوز نیاز به تأیید روی سیستم دارای Docker دارد.
این ارزیابی تست سودآوری یا تأیید معاملهٔ واقعی نیست.
