# سه ربات LBank: شاهین، موج‌سوار، ققنوس — و داشبورد فارسی

## سه ربات (پیش‌فرض: هر سه روشن، حساب paper مشترک، سقف مارجین ۸۰٪)

| نام | کار | ارزها | ریسک پیش‌فرض | فایل |
|---|---|---|---|---|
| **شاهین** (Shahin، ربات اصلی) | شکست Donchian10 + Kumo روی کندل ۴ساعته، فیلتر ATR و کف سود ۱R | BTC، ETH، SOL، XRP، ADA | ۱٪ | `lbank_bot.py`، `config.json` |
| **موج‌سوار** (Mojsavar، همان C3+D) | پولبک در روند ۴ساعته (EMA50/200 + RSI) با تأیید ۳ کندل | ۱۰ ارز | ۰٫۴٪ | `c3_sleeve.py`، `c3_config.json` |
| **ققنوس** (Ghoghnous، همان PA) | پرایس‌اکشن Key Reversal ۴ساعته (نسخهٔ C2)، ورود Stop فقط در رژیم کم‌نوسان، رد کندل سیگنال کوچک‌تر از 1.1 ATR، خروج با استاپ، Key Reversal مخالف یا بعد از ۳۰ کندل | ۲۰ ارز دیگر | ۰٫۴٪ | `pa_sleeve.py`، `pa_config.json` |

در داشبورد، پنل «سه ربات» برای هرکدام یک کلید روشن/خاموش دارد. خاموش کردن فقط ورود جدید همان ربات را متوقف می‌کند (سفارش‌های پرنشده لغو می‌شوند) و پوزیشن‌های باز تا خروج مدیریت می‌شوند. کلید شاهین همان `bot_control.auto_trade_enabled` است و کلید دو ربات دیگر `enabled` در فایل تنظیماتشان. API: `POST /api/bots/toggle` با `{"bot": "main"|"c3"|"pa", "enabled": true|false}`. نام‌های C3 و PA در کد (نام فایل‌ها و مسیرهای `/api/c3` و `/api/pa`) برای سازگاری حفظ شده‌اند.

سقف مجموع مارجین هر سه ربات (`risk_and_exit.engaged_capital_pct`) از ۶۰٪ به **۸۰٪** رسید. در runtime موجود با `python apply_shared_capital.py --config runtime/config.json --c3-config runtime/c3_config.json --pa-config runtime/pa_config.json` اعمال کنید. تنظیمات قدیمی ققنوس که دست‌نخورده‌اند (هدف 2R، ریسک ۰٫۱۵٪) خودکار به پیش‌فرض جدید ارتقا می‌یابند. بک‌تست سه ربات از ۲۰۲۱ روی یک حساب: `high_cagr/ideas/three_bots_replay.py` و گزارش `high_cagr/output/ideas/three_bots/report_fa.html`.

این بسته شامل کد ربات، داشبورد، تنظیمات بهینه‌شده، تست‌های قابل اجرا و گزارش تست است. موتور استراتژی، مدیریت پوزیشن و داشبورد اجرا می‌شوند. **اجرای سفارش زندهٔ فیوچرز در این نسخه موجود نیست؛ نسخهٔ قابل اجرا برای شبیه‌سازی است.**

## محدودیت واقعی اتصال LBank

کد نسخهٔ نصب‌شدهٔ `ccxt==4.5.85` بررسی شد:

- `fetch_ticker` برای نمادهای Swap از API عمومی قرارداد استفاده می‌کند.
- `create_order` به endpoint اسپات می‌رود؛ `defaultType=swap` آن را به ثبت سفارش فیوچرز تبدیل نمی‌کند.
- `fetch_ohlcv` نیز به endpoint اسپات می‌رود.
- تنظیم اهرم، حالت مارجین، سفارش reduce-only و خواندن پوزیشن فیوچرز در این adapter پشتیبانی نشده‌اند.

به همین علت `dry_run_mode=false` با خطای واضح رد می‌شود. هیچ مسیر ارسال سفارش، خصوصی یا اسپات، در موتور وجود ندارد. نمی‌توان این نسخه را آمادهٔ معامله با سرمایهٔ واقعی دانست. برای افزودن اجرای زنده، مستندات معتبر endpointهای خصوصی فیوچرز، سفارش و fill، بازیابی سفارش پس از timeout، تطبیق پوزیشن پس از restart و حفاظت سمت صرافی لازم است.

منابع بررسی:

- https://github.com/ccxt/ccxt/blob/master/python/ccxt/lbank.py
- https://github.com/ccxt/ccxt/wiki/ccxt-vs-lbank-api
- https://www.lbank.com/docs/contract.html

## اجرای سریع با Docker

در پوشهٔ پروژه:

```bash
cp .env.example .env
```

مقدار `BOT_PIN` در `.env` را با PIN دلخواه خود جایگزین کنید. سپس:

```bash
docker compose up -d --build
docker compose logs -f lbank-bot
```

داشبورد را در `http://localhost:8000` باز کنید و همان PIN را وارد کنید. پورت روی loopback میزبان تنظیم شده است.

حالت پیش‌فرض `PAPER_DATA_MODE=demo` کاملاً آفلاین است و **کندل و قیمت مصنوعی** تولید می‌کند. برچسب `demo` روی داشبورد نمایش داده می‌شود. نیازی به API Key نیست. سرمایهٔ اولیهٔ شبیه‌سازی با `PAPER_EQUITY` تعیین می‌شود؛ پیش‌فرض ۱۰٬۰۰۰ دلار است.

اولین اجرا کانفیگ پیش‌فرض را به `runtime/config.json` کپی می‌کند. پس از آن فایل داخل `runtime` مرجع اصلی است. تغییر `config.json` کنار کد، کانفیگ ذخیره‌شدهٔ اجرای Docker را تغییر نمی‌دهد. هر دو کانتینر پوشهٔ `runtime` را مشترک دارند تا `os.replace`، فایل‌های قفل و SQLite WAL درست کار کنند. Mount کردن تنها فایل کانفیگ با ذخیرهٔ اتمیک سازگار نیست.

برای توقف سرویس‌ها:

```bash
docker compose down
```

توقف سرویس، پوزیشن‌های شبیه‌سازی‌شده را از دیتابیس حذف نمی‌کند. برای بستن آن‌ها از داشبورد استفاده کنید. این بسته روی دادهٔ خالی شروع می‌شود و ابزار مهاجرت دیتابیس نسخه‌های دیگر ندارد.

## اجرا بدون Docker

Linux یا macOS و Python نسخهٔ ۳.۱۱ یا بالاتر لازم است. قفل‌ها از `fcntl` استفاده می‌کنند؛ روی Windows از Docker استفاده کنید.

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements-dev.txt
export BOT_PIN='my-personal-pin'
export PAPER_DATA_MODE=demo
python -u lbank_bot.py
```

در ترمینال دوم، در همان پوشه و با همان محیط مجازی:

```bash
source .venv/bin/activate
export BOT_PIN='my-personal-pin'
export PAPER_DATA_MODE=demo
uvicorn dashboard_server:app --host 127.0.0.1 --port 8000
```

در اجرای محلی، مسیر پیش‌فرض کانفیگ `config.json` و دیتابیس `data/lbank_ichimoku_bot.db` است. متغیرهای `BOT_CONFIG` و `BOT_DB` قابل تغییر هستند و باید برای دو پردازش یکسان باشند. اگر `BOT_PIN` محلی تنظیم نشود، مقدار درخواستی مشخصات، یعنی `1234`، استفاده می‌شود؛ در Docker تنظیم آن الزامی است.

## دادهٔ واقعی فیوچرز برای شبیه‌سازی

`PAPER_DATA_MODE=csv-lbank` قیمت عمومی قراردادهای LBank را می‌خواند، اما کندل‌ها باید از CSV فیوچرز تهیه‌شده توسط خودتان دریافت شوند. هیچ کندل اسپاتی به‌جای فیوچرز استفاده نمی‌شود. فایل مفقود، قدیمی، دارای gap یا نامعتبر باعث جلوگیری از سیگنال همان نماد و تلاش مجدد می‌شود.

در Docker فایل‌ها را در `runtime/ohlcv` بگذارید. در اجرای محلی پیش‌فرض `data/ohlcv` است و با `OHLCV_DIR` تغییر می‌کند. نام‌گذاری نمونه:

```text
BTC_USDT_USDT_1h.csv
BTC_USDT_USDT_4h.csv
ETH_USDT_USDT_1h.csv
ETH_USDT_USDT_4h.csv
```

برای هر نماد و هر تایم‌فریم مصرف‌شده، فایل باید با این ترتیب ستون‌ها موجود باشد:

```csv
timestamp,open,high,low,close,volume
```

`timestamp` زمان باز شدن کندل، با Unix milliseconds و مرزهای UTC است. ردیف‌ها باید صعودی، پیوسته و یکتا باشند. حداقل ۲۰۰ ردیف نگه دارید و آخرین ردیف را به کندل جاری اختصاص دهید؛ این ردیف طبق مشخصات همیشه حذف می‌شود. فایل‌ها باید مرتب به‌روزرسانی شوند تا آخرین کندل بسته‌شده با مرز زمانی فعلی مطابقت داشته باشد. تولیدکنندهٔ داده باید CSV را با فایل موقت و rename اتمیک جایگزین کند.

اگر داده یا قیمت قابل دریافت نباشد، خروج مربوط به آن نماد انجام نمی‌شود و ردیف پوزیشن حفظ می‌شود؛ این موضوع در پاسخ Panic و وضعیت نمایش داده می‌شود. این رفتار فقط شبیه‌سازی است و هیچ سفارش حفاظتی روی صرافی وجود ندارد.

## رفتار موتور

- فقط کندل‌های بسته‌شده برای Ichimoku، RSI، ATR، H2/L2، Barb Wire و کندل سیگنال مصرف می‌شوند. RSI و ATR با SMA اولیه و هموارسازی Wilder محاسبه می‌شوند.
- حالت MTF از روند HTF و ورود LTF استفاده می‌کند؛ حالت SINGLE از یک تایم‌فریم.
- اسکن اولیه پس از شروع و اسکن بعدی سه ثانیه بعد از مرز کندل انجام می‌شود. خطای داده پس از ده ثانیه دوباره امتحان می‌شود. کندل ارزیابی‌شده در دیتابیس ثبت می‌شود تا دوباره سیگنال ندهد.
- Watchdog و اسکنر جدا اجرا می‌شوند. عملیات تغییر پوزیشن در ربات و داشبورد با قفل مشترک بین پردازش‌ها انجام می‌شود. ثبت PnL و به‌روزرسانی یا حذف پوزیشن یک تراکنش SQLite است.
- سفارش در انتظار، انقضا، لغو، ورود، حد ضرر، TP1 و دنبال‌کردن Kijun پیاده‌سازی شده‌اند. حجم در Gap ورود دوباره کم می‌شود و TP1 با قیمت ورود جدید محاسبه می‌شود.
- حجم CCXT بر اساس تعداد قرارداد و `contractSize` محاسبه می‌شود. در DEMO مشخصات قرارداد شبیه‌سازی است و اندازهٔ حداقلی دقیق صرافی را بازنمایی نمی‌کند.
- اگر خروج جزئی یا باقی‌مانده زیر حداقل حجم باشد، کل پوزیشن در TP1 بسته می‌شود.
- خاموش‌کردن ورود خودکار، setupهای پرنشده را لغو می‌کند؛ مدیریت پوزیشن‌های باز ادامه دارد. Panic علاوه بر توقف ورود، همهٔ پوزیشن‌ها را برای بستن بررسی می‌کند.
- محدودیت زیان روزانه طبق فایل ورودی، بازهٔ شناور ۲۴ ساعت است. در زمان فعال‌شدن تریگر نیز دوباره بررسی می‌شود.
- کارمزد round-trip بین ارزش ورود و خروج تقسیم می‌شود. سود و زیان از مقدار پایه، قیمت ورود و خروج و کارمزد محاسبه می‌شود. Funding، لغزش، liquidation و تغییر قیمت طی فراخوانی API مدل نشده‌اند؛ خروج‌ها در آخرین قیمت مشاهده‌شده شبیه‌سازی می‌شوند.
- شمارندهٔ معاملات ۲۴ ساعت، تعداد خروج‌های ثبت‌شده است؛ TP1 و خروج باقی‌مانده دو رکورد هستند.
- سرمایهٔ اولیه در دیتابیس ذخیره می‌شود. تغییر بعدی `PAPER_EQUITY` سرمایهٔ همان دیتابیس را reset نمی‌کند.

جداول پایهٔ `positions` و `trade_history` دارای ستون‌های اضافی برای مشخصات قرارداد و حسابداری هستند. `scanned_candles` جلوگیری از تکرار سیگنال و `runtime` وضعیت پردازش‌ها را نگه می‌دارد.

## API و تست‌ها

همهٔ مسیرهای `/api/*` به هدر `X-Bot-Pin` نیاز دارند. صفحهٔ HTML بدون PIN باز می‌شود، اما اطلاعات حساب را بدون PIN دریافت نمی‌کند. مسیرها:

- `GET /api/status`
- `GET /api/config`
- `PUT /api/config`
- `POST /api/positions/close` با JSON شامل `symbol`
- `POST /api/positions/close-all` با JSON شامل `disable_auto_trade`

API کانفیگ `ETag` می‌دهد. ارسال آن با `If-Match` از بازنویسی تغییر هم‌زمان جلوگیری می‌کند؛ داشبورد این کار را انجام می‌دهد. مقادیر عددی، schema، تایم‌فریم‌ها و محدودهٔ ریسک ۰٫۱ تا ۵ درصد بررسی می‌شوند. PIN داخل مرورگر فقط در حافظه نگه داشته می‌شود.

```bash
python -m pytest tests -q
node tests/test_ui.cjs
```

تست Python، دو پردازش واقعی ربات و Uvicorn را در حالت DEMO راه‌اندازی و سپس متوقف می‌کند. هیچ سفارش واقعی ارسال نمی‌شود. تست JavaScript منطق DOM را بررسی می‌کند و جای تست بصری مرورگر را نمی‌گیرد. نتایج اجرا و محدودیت‌های بررسی در `TEST_REPORT.md` موجود است.

## تنظیمات پس از بنچمارک چهار خانواده

پیکربندی BTC مرحلهٔ قبل، در portfolio/prior/config.json نگه داشته شده است. مشخصات آن: DONCHIAN با SINGLE چهار‌ساعته و فقط BTC. ایچیموکو (9,26,52,26)، شکست Close بالاتر/پایین‌تر از کانال 20 کندل قبلی و بیرون Kumo؛ ورود بازار پس از بسته‌شدن. استاپ اولیه Kijun(26)، حداقل استاپ 1.2% با REJECT در سیگنال و fill واقعی، و تریل روی extreme مخالف 10 کندل بسته؛ بدون خروج جزئی، سربه‌سر یا هدف ثابت. RSI، ADX، Barb Wire و H2/L2 در این خانواده اعمال نمی‌شوند. مسیر چهار خانواده در strategy_archetypes.py تعریف شده است؛ این فایل باید کنار lbank_bot.py باشد.

112 پیکربندی در سه دوره اجرا شد؛ 17 ترکیب شرط حداقل 40 معامله و سود مثبت آموزش و دوره بعدی را گذراندند. برنده 288 معامله و $2,984.14 سود کل، $2,773.88 سود آموزش و $163.82 سود 2025–2026 داشت. دوره بعدی برای انتخاب استفاده شده و آزمون مستقل دست‌نخورده نیست. هیچ ترکیب واجدشرایط در محدوده 40–60 معامله یافت نشد. هدف فرکانس 25–60 معامله پنج‌ساله محقق نشد.

تنظیمات هر پوزیشن ساخته‌شده در نسخه جدید در SQLite ذخیره می‌شوند؛ تغییر config اندیکاتور، stop یا trail همین پوزیشن‌های ذخیره‌شده را عوض نمی‌کند. پوزیشن‌های قدیمی بدون snapshot فقط پارامترهای خروج و تایم‌فریمِ موجود در رکورد خود را حفظ می‌کنند؛ اندیکاتورهای ذخیره‌نشدهٔ قدیمی قابل استنتاج نیستند. سفارش شکست در خانواده‌های مربوط GTC است و با تغییر جهت رژیم یا برخورد استاپ سیگنال لغو می‌شود. مهاجرت پایگاه داده پوزیشن‌های قدیمی را حفظ می‌کند. حالت paper حفظ شده؛ PnL نمایشی ربات فقط کارمزد دارد. Funding و لغزش در بک‌تست اعمال شده‌اند. Funding چهار روز اول اکتبر آرشیوی نبود؛ برنده یک هزینه فرضی $0.37 دارد که در گزارش مشخص شده است.

## مدیریت مارجین و خروج قابل تنظیم Donchian

پیش‌فرض ارتقای سرمایه شامل پنج نماد BTC، ETH، SOL، XRP و ADA است. منطق
ورود همان Donchian20 + Kumo روی کندل بستهٔ ۴ ساعته با پریست crypto، استاپ
ATR2 و خروج CLOSE_TRAIL_KIJUN باقی می‌ماند. حداقل استاپ ۱٫۲٪ با REJECT
هم در سیگنال و هم در قیمت ورود بررسی می‌شود.

- `risk_and_exit.engaged_capital_pct=0.60`: سقف مارجین کل، نه هدف مصرف اجباری.
- `max_open_positions=4`: بودجه هر اسلات برابر equity × 0.60 / 4 است.
- `risk_per_trade_pct=0.005`: ریسک دلار از کل equity محاسبه می‌شود.
- `leverage_mode=DYNAMIC_MARGIN`: اهرم صحیح ۱ تا `default_isolated_leverage=5`
  از ceil(target_notional / slot_margin) تعیین می‌شود. در FIXED_LEVERAGE
  اهرم همیشه مقدار ثابت تنظیم‌شده است.
- حجم بر مبنای فاصله استاپ + کارمزد رفت‌وبرگشت ۰٫۱۲٪ + ذخیره لغزش ۰٫۰۴٪
  تعیین می‌شود. محدودیت مارجین و گرد کردن مقدار، ریسک را فقط کاهش می‌دهند.
  این ذخیره لغزش تضمین قیمت اجرای سفارش یا زیان دقیق در گپ بازار نیست.
- اهرم واقعی در دیتابیس هر پوزیشن ذخیره می‌شود؛ معاملات قدیمی در مهاجرت
  از اهرم کانفیگ ذخیره‌شدهٔ خود استفاده می‌کنند. رزرو سفارش‌های در انتظار
  نیز برای پذیرش معاملات جدید شمرده می‌شود.
- رسیدن PnL تحقق‌یافته خالص ۲۴ ساعت اخیر به زیان ۲٪ equity ورود جدید را
  متوقف می‌کند؛ خروج و مدیریت ریسک معاملات موجود ادامه دارد.

بخش `strategy_settings` مرجع تنظیمات Donchian است و کلیدهای قدیمی موتور
هنگام اعتبارسنجی از آن ساخته می‌شوند. `ichimoku_preset` دو مقدار crypto و
standard، `donchian_entry_period` دو مقدار ۲۰ و ۱۰ و `initial_stop_mode`
دو مقدار ATR2 و KIJUN را می‌پذیرند.

`exit_tp_mode` شامل STOP_TRAIL_DONCHIAN10 (استاپ پله‌ای کف/سقف ۱۰ کندل
بسته)، CLOSE_TRAIL_KIJUN (استاپ اولیه + خروج با کلوز نامطلوب کیجون) و
HYBRID_TRAIL_AND_HARD_TP است. در حالت ترکیبی، `hybrid_trail_mode` تریل
زیرین را انتخاب می‌کند و `hard_tp_rr` باید مثبت باشد. مقدار مثبت
`hard_tp_rr` در سایر حالت‌ها هم هدف قطعی را فعال می‌کند. صفر یعنی خاموش.
`breakeven_trigger_rr=0` پیش‌فرض خاموش است؛ مقدار ۲ استاپ را با رسیدن
قیمت به ۲R به ورود منتقل می‌کند، بدون خروج جزئی.

Hot-Reload برای ورودهای بعدی اعمال می‌شود؛ قواعد خروج، هدف، فاصله R و
تایم‌فریم معاملات باز تغییر نمی‌کنند. داشبورد مارجین درگیر واقعی، درصد
آن از equity و درصد مصرف بودجه مجاز را نشان می‌دهد و رزرو سفارش‌های
در انتظار را جداگانه نمایش می‌دهد. با خطای قیمت، درصدهای وابسته به equity
نامشخص نمایش داده می‌شوند، نه صفر ساختگی.

این تغییرات، تنظیمات اجرایی درخواستی‌اند؛ نتایج بک‌تست ذخیره‌شده مربوط
به پرتفوی شش‌نمادی و ریسک ۰٫۳۷۵٪ قبلی است و بازنویسی نشده است.
موتور فعلی همچنان paper-only است: حد سود، استاپ و اهرم در شبیه‌ساز
اجرا می‌شوند؛ اتصال فعلی CCXT امکان سفارش فیوچرز زنده و TP بومی LBank
را فراهم نمی‌کند.

## موج‌سوار (C3: پولبک در روند ۴ساعته) روی ۱۰ ارز دیگر — فقط paper

C3 جزء خود ربات است: `python lbank_bot.py` (و سرویس `lbank-bot` در Docker) آن را در یک thread جدا با تنظیمات `c3_config.json` و دیتابیس جدا (`data/c3_sleeve.db` یا `runtime/c3_sleeve.db` در Docker) اجرا می‌کند. استراتژی و تنظیمات ربات اصلی دست نمی‌خورند و خطای C3 ربات را متوقف نمی‌کند. اندازهٔ پوزیشن‌های C3 از سرمایهٔ مشترک حساب می‌شود (سرمایهٔ paper ربات + سود/زیان بسته‌شدهٔ C3). **خلاصهٔ تفکیکی و جدول مشترک:** بالای داشبورد سه نمای «هر دو / ربات اصلی / C3+D» دارد (انتخاب در مرورگر ذخیره می‌شود) و سرمایه، سود و زیان باز، سود ۲۴ ساعت، تعداد پوزیشن و مارجین/نُوشنال را برای همان نما نشان می‌دهد. پوزیشن‌های هر دو استراتژی در یک جدول با ستون «استراتژی» هستند و هر ردیف دکمهٔ بستن/لغو خودش را دارد. **کنترل از همان داشبورد:** در پنل «استراتژی دوم: C3+D» می‌توانید ورود جدید را روشن/خاموش کنید، ریسک، سقف نُوشنال، تأیید ورود D، فیلتر آخر هفته و فهرست نمادها را عوض کنید (یا JSON کامل را ویرایش کنید)، پوزیشن‌ها و ۲۰ معاملهٔ اخیر را ببینید و هر پوزیشن را آنی ببندید. ذخیرهٔ تنظیمات بدون ری‌استارت در چند ثانیه اعمال می‌شود؛ فقط حالت paper پذیرفته می‌شود (`dry_run_mode` اجباری true). دکمهٔ «بستن اضطراری» هر دو استراتژی را می‌بندد و ورود جدید هر دو را متوقف می‌کند. خاموش کردن کامل thread: متغیر محیطی `C3_IN_BOT=0`. سرویس dashboard در Docker هم `C3_CONFIG` و `C3_DB` را دارد.

- **قواعد (کندل بستهٔ ۴ساعته):** لانگ وقتی EMA50 بالای EMA200 است و RSI14 از ۴۰ به بالا عبور می‌کند؛ شورت برعکس (EMA50 زیر EMA200، RSI از ۶۰ به پایین). کندل سیگنالی که شنبه/یکشنبه (UTC) بسته شود معامله نمی‌شود. استاپ اولیه ۲ ATR، سپس تریل: بهترین Close منهای ۴٫۵ ATR که فقط جلو می‌رود.
- **ارزها:** AAVE، UNI، AVAX، KSM، EGLD، DOT، DOGE، ONE، TRX، SUSHI (۱۰ ارز برتر بر اساس سود C3 در دورهٔ Train میان ۳۰ ارز آزموده‌شده). باید پیش از اجرا بررسی شود که قرارداد USDT دائمی همهٔ آن‌ها در LBank فعال است؛ نماد ناموجود فقط خطا ثبت می‌کند.
- **ریسک:** ۰٫۲٪ سرمایه در هر معامله (ربات ۰٫۷۵٪ + C3+D ‏۰٫۲٪ = بهترین ترکیب با شرط افت Train ≤ ۲۰٪ در `high_cagr/output/ideas/risk_sweep/`: بک‌تست CAGR ۶۶٪ / افت ۲۰٪). فایل runtime قدیمی که هنوز ۰٫۱۵٪ پیش‌فرض را دارد خودکار به ۰٫۲٪ ارتقا می‌یابد و کلیدهای جدید (مثل `confirm_bars`) به آن اضافه می‌شوند؛ مقداری که خودتان عوض کرده‌اید دست نمی‌خورد، سقف نُوشنال ۴۰٪ برای هر پوزیشن، `dry_run_mode` اجباری true.
- **شواهد:** روی ۲۰ ارز کاملاً دست‌نخورده CAGR ۲۱٪ با افت ۳۸٪ (Calmar Train/Validation ‏0.61/0.51) و ۱۹ از ۲۰ ارز سودده؛ همبستگی با ربات اصلی حدود ۰٫۲۵ تا ۰٫۳۵. نتیجهٔ ترکیبی بک‌تست (ربات + C3 با ۰٫۲۵٪) خوش‌بینانه است، چون ارزها با نگاه به سود انتخاب شده‌اند.
- **اجرای جداگانه (اختیاری):** `PAPER_DATA_MODE=csv-lbank python c3_sleeve.py` (فایل‌های CSV فیوچرز ۴ساعتهٔ این ۱۰ ارز در `OHLCV_DIR` لازم است؛ حداقل ۱۰۰۰ کندل برای گرم شدن EMA200). در حالت عادی لازم نیست؛ ربات خودش C3 را اجرا می‌کند. اجرای جداگانه فقط با `C3_IN_BOT=0` روی ربات (وگرنه C3 دوبار اجرا می‌شود).
- **تأیید ورود (نسخهٔ D، پیش‌فرض):** `confirm_bars: 3` — بعد از سیگنال پولبک، ورود فقط وقتی انجام می‌شود که تا ۳ کندل بعد، بستهٔ کندلی از بستهٔ کندل سیگنال فراتر برود (برای شورت پایین‌تر) و روند EMA50/200 برنگشته باشد؛ ورود در قیمت بعد از کندل تأییدکننده و استاپ ۲ATR همان کندل. کندل تأیید هم نباید در آخر هفته بسته شود. سیگنال‌های در انتظار در جدول `pending` ذخیره می‌شوند. مقدار ۰ = C3 قدیمی. بک‌تست ۱۰ ارز (ریسک ۰٫۵٪): CAGR ۴۷٫۵٪ / افت ۲۷٫۴٪ با Calmar Train/Valid ‏1.85/2.28، در برابر CAGR ۵۲٫۴٪ / افت ۳۸٫۲٪ و Calmar ‏1.38/2.15 بدون تأیید (سود کمی کمتر، افت خیلی کمتر).
- **تست‌ها:** `tests/test_c3_sleeve.py` سیگنال و ATR را روی دادهٔ واقعی با موتور بک‌تست مقایسه می‌کند (یکسان) و چرخهٔ ورود/تریل/استاپ را می‌آزماید؛ ورودهای تأییدشدهٔ D هم کندل‌به‌کندل با بک‌تست یکسان‌اند.


## مدیریت سرمایهٔ مشترک شاهین و موج‌سوار (Paper؛ اکنون ققنوس هم)

پیش‌فرض جدید: ریسک ربات اصلی ۱٪ (از ۰٫۷۵٪ با ضریب ۱٫۳۳ افزایش یافت؛ ببینید پایین)، ریسک C3 برابر ۰٫۴٪ و سقف **مجموع مارجین** هر دو برابر ۶۰٪ Equity مشترک است. Equity شامل یک سرمایهٔ اولیه، سود/زیان تحقق‌یافته و سود/زیان بازِ هر دو با هزینهٔ رفت‌وبرگشت است. سفارش‌های در انتظار اصلی نیز مارجین رزرو می‌کنند. اهرم ایزولهٔ C3 برابر ۵ است و برای هر پوزیشن ذخیره می‌شود؛ رکوردهای قدیمی فاقد اهرم نیز در حساب Paper با ۵ محاسبه می‌شوند.

کلید `portfolio_risk.shared_c3_account` این مدیریت را فعال می‌کند. ورود، خروج و افزودن با قفل مشترک دو موتور هماهنگ می‌شود؛ با نبود قیمت معتبر برای پوزیشن C3، ورود جدید متوقف می‌شود. داشبورد مجموع مارجین را نمایش می‌دهد. سقف ۶۰٪ هدف مصرف دائمی نیست؛ تعداد سیگنال‌ها و فاصلهٔ استاپ مصرف واقعی را تعیین می‌کنند. قواعد ورود و خروج استراتژی‌ها تغییر نکرده‌اند.

برای ارتقای تنظیمات runtime موجود، ابتدا دو سرویس را متوقف کنید و از پوشهٔ `lbank_project` اجرا کنید:

```bash
git pull origin master
docker compose stop
python apply_shared_capital.py --config runtime/config.json --c3-config runtime/c3_config.json
docker compose up -d --build
```

اسکریپت تنظیمات سیگنال و خروج موجود را حفظ می‌کند، ریسک‌ها و سقف مشترک را اعمال می‌کند و هر دو را در حالت Paper قرار می‌دهد. اجرای آن به وابستگی‌های `requirements.txt` نیاز دارد. اگر مسیر تنظیمات شما متفاوت است، همان مسیرهای `BOT_CONFIG` و `C3_CONFIG` را به اسکریپت بدهید. دیتابیس‌های دو سرویس باید مشترک باشند؛ تنظیمات Docker موجود این کار را انجام می‌دهد.

این تخصیص از مقایسهٔ مقدماتی کندل‌های ۴ساعته انتخاب شده؛ این ارتقا تأیید بک‌تست یک‌دقیقه‌ای جدید یا اجرای واقعی LBank نیست. کاهش Equity بر اثر زیان می‌تواند نسبت مارجین پوزیشن‌های موجود را از سقف بالاتر ببرد؛ سقف، ورود و افزایش حجم جدید را محدود می‌کند و پوزیشن موجود را اجباری نمی‌بندد.

## بودجهٔ مشترک بدون تقسیم اسلات (نسخهٔ جدید Paper)

`portfolio_risk.margin_allocation_mode="SHARED_POOL"` سقف نوشنال ناشی از تقسیم اسلات‌های اصلی و سقف مستقل `max_notional_pct` در C3 را غیرفعال می‌کند؛ C3 برای این رفتار باید به حساب مشترک متصل باشد. سقف تعداد همچنان مستقل است: چهار پوزیشن اصلی (شامل سفارش‌های در انتظار) و C3 بدون سقف تعداد (`max_open_positions=0`). برای هر نماد همچنان فقط یک پوزیشن C3 باز می‌شود؛ ریسک و مارجین آزاد مشترک ورود را محدود می‌کنند. کاهش سقف در Hot-Reload پوزیشن موجود را نمی‌بندد و تنها ورود جدید را محدود می‌کند. ترتیب نمادهای C3 تعیین‌کنندهٔ تقدم ورود است.

ریسک روی **کل Equity مشترک** است: اصلی ۱٪، C3 برابر ۰٫۴٪، اهرم ثابت ۵ و سقف مارجین مجموع ۶۰٪. این مقادیر جایگزین مقادیر تاریخی بخش‌های بالاتر هستند. در هر ورود حجم هدف = Equity × درصد ریسک ÷ (فاصلهٔ استاپ نسبی + ۰٫۱۲٪ کارمزد + ۰٫۰۴٪ لغزش)؛ حجم نهایی با مارجین آزاد مشترک و دقت سفارش محدود می‌شود. سقف ۶۰٪ هدف مصرف اجباری نیست. تغییر اهرم به‌تنهایی سود همان حجم را زیاد نمی‌کند.

حالت `PER_SLOT` رفتار پیشین را بازمی‌گرداند؛ کانفیگ‌های قدیمی که کلید جدید را ندارند نیز همین رفتار را حفظ می‌کنند. برای اعمال دقیق پیش‌فرض جدید روی runtime موجود از دستور `apply_shared_capital.py` بالا استفاده کنید. این دستور حالت Paper، سقف چهار برای اصلی و حذف سقف تعداد C3، اهرم ثابت ۵ و حالت SHARED_POOL را تنظیم می‌کند و تنظیم سیگنال و خروج شما را حفظ می‌کند. هیچ انتقال وجه یا سفارش واقعی اجرا نمی‌شود.

برای حذف سقف چهار از runtime موجود، مقدار `max_open_positions` در پنل C3 را روی ۰ ذخیره کنید یا اسکریپت `apply_shared_capital.py` را با مسیر تنظیمات واقعی اجرا کنید. `git pull` به‌تنهایی مقدار ۴ در فایل runtime قبلی را تغییر نمی‌دهد. تنظیم محدودیت تعداد مثبت در آینده همچنان پشتیبانی می‌شود.

## ریسک پیش‌فرض شاهین (ربات اصلی): ۱٪

مطالعهٔ `high_cagr/ideas/conviction_2x.py` (قانون از پیش ثبت‌شده) نشان داد هیچ ویژگی ورود (ADX، فاصلهٔ EMA، کومو، شکست، ATR، روند ۵۰ روزه، روند BTC، RSI) ریسک دوبرابرِ انتخابی را توجیه نمی‌کند؛ نرخ برد در همهٔ گروه‌ها ۴۳ تا ۴۹٪ است. بهترین قانون (RSI) در Validation با Calmar 2.37 و افت ۲۷٪ رد شد، در حالی که همان ریسک متوسط به‌صورت یکنواخت (×۱٫۳۳ روی همهٔ معاملات) Validation را با سود ۶۷٪، افت ۲۳٪ و Calmar 2.89 گذراند (ربات ۰٫۷۵٪: ۵۱٪ / ۱۸٪ / 2.81). بنابراین ریسک پیش‌فرض ربات اصلی ۱٪ شد. افت سرمایه حدود ۱٫۳ برابر می‌شود. فایل runtime موجود با `git pull` عوض نمی‌شود؛ از پنل تنظیمات یا `apply_shared_capital.py` اعمال کنید.

## ققنوس (PA: پرایس‌اکشن Key Reversal ۴ساعته) روی ۲۰ ارز دیگر — فقط paper

ربات حالا **سه استراتژی هم‌زمان** روی یک حساب paper مشترک اجرا می‌کند: ربات اصلی (۵ ارز، ریسک ۱٪)، C3+D (۱۰ ارز، ۰٫۴٪) و PA (۲۰ ارز دیگر، **۰٫۱۵٪**). هیچ نمادی بین دو استراتژی مشترک نیست. PA مثل C3 در یک thread جدا داخل `lbank_bot.py` اجرا می‌شود (`pa_sleeve.py`، تنظیمات `pa_config.json`، دیتابیس `data/pa_sleeve.db` یا `runtime/pa_sleeve.db`؛ خاموش کردن thread با `PA_IN_BOT=0`). خطای PA ربات را متوقف نمی‌کند. سرمایه، سود/زیان باز و مارجین PA در حساب مشترک و سقف ۶۰٪ مارجین شمرده می‌شود. داشبورد پنل «استراتژی سوم: PA» دارد (روشن/خاموش، ریسک، نمادها، JSON کامل، سفارش‌های Stop در انتظار، ۲۰ معاملهٔ اخیر) و پوزیشن‌های PA در جدول مشترک با برچسب PA و دکمهٔ بستن نمایش داده می‌شوند. «بستن اضطراری» هر سه را می‌بندد و ورود هر سه را متوقف می‌کند.

- **قاعدهٔ ورود (کندل بستهٔ ۴ساعته):** لانگ وقتی کندل Outside است (سقف بالاتر و کف پایین‌تر از کندل قبل)، کفش پایین‌ترین کف ۱۱ کندل اخیر است، Close بالاتر از Close قبلی و در ۲۵٪ بالای رنج کندل بسته شده. شورت دقیقاً قرینه. ورود با **سفارش Stop** روی سقف کندل سیگنال (شورت: کف)، فقط تا بسته‌شدن کندل بعد؛ اگر قیمت قبل از فعال‌شدن به حد ضرر برسد سفارش لغو می‌شود.
- **خروج:** حد ضرر = کف کندل سیگنال − ۰٫۱ ATR14؛ **هدف ثابت ۲R**؛ خروج زمانی در Close سی‌امین کندل بعد از ورود. استاپ کمتر از ۰٫۴٪ قیمت رد می‌شود.
- **ارزها:** ATOM، FIL، LTC، AXS، LINK، XTZ، ALGO، ETC، NEAR، CELR، BCH، ALICE، C98، 1000SHIB، THETA، IOST، CVC، CRV، IOTA، VET (۲۰ ارز آزموده‌شده‌ای که ربات اصلی و C3 معامله نمی‌کنند؛ بر اساس سود انتخاب نشده‌اند). پیش از اجرا بررسی کنید قرارداد دائمی هرکدام در LBank با همین نام وجود دارد (مخصوصاً 1000SHIB، CVC، C98، CELR، ALICE)؛ نماد ناموجود فقط خطا ثبت می‌کند و می‌توانید از پنل حذفش کنید.
- **چرا این؟** آزمون از پیش ثبت‌شدهٔ `high_cagr/ideas/pa_bot.py`: ۱۹ روش ورود پرایس‌اکشن (H2 بروکس، رد EMA20، شکست و پولبک، Inside Bar، فلگ، BOS، FVG، NR7، شکست باکس، پین‌بار، اینگالفینگ، دابل‌باتم، SFP/شکار نقدینگی، فیکی، تلهٔ شکست، وج، CHoCH، Key Reversal، کلایمکس) × ۱h/۴h × سه خروج × دو فیلتر = ۲۲۸ حالت، با دادهٔ دقیقه‌ای واقعی و کارمزد/لغزش/Funding. فقط ۹٪ حالت‌ها در کل دوره سودده بودند، تمام نسخه‌های ۱ساعته زیان‌ده بودند (کارمزد با استاپ‌های کوتاه)، و فقط **۴h KEYREV با هدف 2R** همهٔ شرط‌ها را گذراند. نتایج در `high_cagr/output/ideas/pa_bot/` (و جدول کامل در `all_configs.csv`).
- **اثر روی کل حساب (بک‌تست):** ربات + C3 بدون PA: CAGR ۱۰۶٫۹٪، افت ۳۰٫۷٪، Calmar 3.48 (Validation 2025–2026: 4.43). با PA در ۰٫۱۵٪: CAGR ۱۱۰٫۸٪، افت ۲۵٫۲٪، Calmar 4.40 (Validation: 5.43). ریسک ۰٫۱۵٪ فقط از روی دورهٔ Train انتخاب شد.
- **محدودیت‌ها (صادقانه):** PA به‌تنهایی لبهٔ ضعیفی دارد: در Train تقریباً سربه‌سر (CAGR −۰٫۶٪ با ریسک ۰٫۵٪)، در Validation +۱۶٫۶٪؛ ۱۴ از ۲۰ ارز سودده؛ سال ۲۰۲۳ حدود −۱۰٪ (در ریسک ۰٫۱۵٪). ارزش اصلی آن **همبستگی تقریباً صفر** با دو ربات دیگر است (۰٫۰۱ و ۰٫۰۳). بخش بزرگی از کاهش افت از این است که PA در دورهٔ افت ۲۰۲۲ (ژوئن تا دسامبر) حدود ۷٫۷٪ سود داشت؛ این ممکن است تکرار نشود. روی ۱۵ ارز دیگر (عمومی‌سازی) Calmar فقط 0.11 بود. پیش از پول واقعی چند ماه paper لازم است.
- **تست‌ها:** `tests/test_pa_sleeve.py` سیگنال، سطح ورود و استاپ را روی دادهٔ واقعی کندل‌به‌کندل با موتور تحقیق مقایسه می‌کند (یکسان)، و چرخهٔ سفارش Stop/لغو/انقضا/هدف/استاپ/خروج زمانی، حساب مشترک و API داشبورد را می‌آزماید.

### بهینه‌سازی ققنوس (جلسهٔ ۱۲ پژوهشگر) — گزینهٔ C1، اکنون پیش‌فرض

۹۶ نسخهٔ از پیش ثبت‌شده (فیلتر روند/نوسان/مومنتوم/محل و زمان، انتخاب ارز، هدف و تریل، کاهش ضرر، اندازهٔ پوزیشن، افزودن، رژیم) روی میز ثابت `high_cagr/ideas/pabench.py` آزموده شد؛ دو نسخهٔ پاس‌شده در بازرسی مستقل رد شدند. آزمون ترکیبی `high_cagr/ideas/pa_opt_combo.py` نشان داد «بدون هدف + حذف کندل سیگنال با رنج کمتر از 1.1 ATR» با ریسک ۰٫۲۵٪، Calmar کل حساب را در بک‌تست از 4.40 به 5.02 می‌رساند (افت ۲۵٫۲٪ ← ۲۵٫۱٪). اجزای آن بعد از دیدن نتایج جلسه انتخاب شده‌اند. به درخواست مالک از ۹ اکتبر ۲۰۲۶ پیش‌فرض است (`"target_r": 0`، `"min_range_atr": 1.1`، `"risk_per_trade_pct": 0.0025`)؛ برای بازگشت به قاعدهٔ اول: `target_r: 2`، `min_range_atr: 0`، ریسک `0.0015`. گزارش کامل: `high_cagr/output/ideas/pa_opt/report_fa.html`.

### ققنوس نسخهٔ C2 (جلسهٔ دوم ۱۲ نفره) — اکنون پیش‌فرض

جلسهٔ دوم (۴ تشخیص‌دهنده + ۸ سازنده + بازرس‌ها، میز ثابت `high_cagr/ideas/pabench2.py`) و آزمون نهایی از پیش ثبت‌شدهٔ `high_cagr/ideas/pa2_final.py` نسخهٔ **F3_vol_opp** را برگزید: همان ورود C1، به‌علاوهٔ (۱) ورود فقط وقتی رتبهٔ ATR/close کندل سیگنال در ۵۰۰ کندل قبلی کمتر از ۰٫۳۵۴ است (`vol_rank_max`، `vol_rank_window`) و (۲) بستن پوزیشن در Close کندلی که Key Reversal مخالف بدهد (`opposite_exit`). ققنوس به‌تنهایی (ریسک ۰٫۵٪ روی پایهٔ ثابت): Calmar کل 0.56 ← 1.82، افت ۳۵٫۹٪ ← ۱۴٫۸٪، روی ۱۵ ارز دیگر 0.60 ← 1.21؛ همهٔ آستانه‌های ۰٫۲۵ تا ۰٫۶ بهتر از C1 بودند. ریسک پیش‌فرض ۰٫۴٪ (قاعدهٔ Train ۰٫۵٪ را برگزید؛ ۰٫۴٪ با Calmar برابر و افت کمتر انتخاب شد). نیاز به ۸۰۰ کندل (`candle_fetch_limit`). تنظیمات runtime دست‌نخوردهٔ C1 خودکار ارتقا می‌یابند. اصلاحات بازبینی کد: خطای log هنگام نبود هدف، تشخیص CSV عقب‌مانده (اسکن دوباره به‌جای گم شدن سیگنال)، پر کردن شکاف‌های کوتاه کندل به‌جای قفل ۵۰ روزه، و `SHIB/USDT:USDT` به‌جای `1000SHIB` (در LBank وجود ندارد). سود و زیان paper همچنان بدون لغزش و Funding گزارش می‌شود (حدود ۱ واحد درصد در سال خوش‌بینانه‌تر). گزارش کامل: `high_cagr/output/ideas/pa_opt2/report_fa.html`.

## کندل‌های زندهٔ LBank (`lbank_candles.py`)

LBank برای فیوچرز endpoint کندل ندارد. سرویس `lbank-candles` هر ۱۰ ثانیه `marketData` عمومی فیوچرز (`lbkperp.lbank.com`) را می‌خواند و کندل ۴ساعته را برای هر ۳۵ نماد می‌سازد و در `runtime/ohlcv/*_4h.csv` می‌نویسد؛ سرویس `lbank-funding` هر ساعت نرخ فاندینگ را ثبت می‌کند. در `.env` مقدار `PAPER_DATA_MODE=csv-lbank` لازم است و سرور باید به LBank دسترسی داشته باشد (خارج از ایران).

محدودیت‌ها: تاریخچه از روز اول اجرا شروع می‌شود (شاهین ≈ ۱۷ روز، موج‌سوار ≈ ۳۴ روز، ققنوس ≈ ۸۳ روز تا گرم شدن)؛ high/low از نمونه‌های هر ۱۰ ثانیه است و سایه‌های بسیار کوتاه ممکن است کم‌تر ثبت شوند؛ حجم کندل ثبت نمی‌شود؛ هر وقفهٔ سرویس در تاریخچه gap می‌شود و ربات تا خروج gap از پنجره آن نماد را رد می‌کند.

**رابط داشبورد (از ۱۰ اکتبر ۲۰۲۶):** کل مرکز کنترل انگلیسی و چپ‌به‌راست است (فونت Inter و JetBrains Mono برای ارقام از Google Fonts). نام ربات‌ها در رابط: Shahin، Mojsavar، Ghoghnous.
