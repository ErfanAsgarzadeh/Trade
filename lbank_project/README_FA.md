# ربات ایچیموکو LBank و داشبورد فارسی

این بسته شامل کد ربات، داشبورد، تنظیمات بهینه‌شده، تست‌های قابل اجرا و گزارش تست است. موتور استراتژی، مدیریت پوزیشن و داشبورد اجرا می‌شوند. **اجرای سفارش زندهٔ فیوچرز در این نسخه موجود نیست؛ نسخهٔ قابل اجرا برای شبیه‌سازی است.**

## محدودیت واقعی اتصال LBank

کد نسخهٔ نصب‌شدهٔ `ccxt==4.5.85` بررسی شد:

- `fetch_ticker` برای نمادهای Swap از API عمومی قرارداد استفاده می‌کند.
- `create_order` به endpoint اسپات می‌رود؛ `defaultType=swap` آن را به ثبت سفارش فیوچرز تبدیل نمی‌کند.
- `fetch_ohlcv` نیز به endpoint اسپات می‌رود.
- تنظیم اهرم، حالت مارجین، سفارش reduce-only و خواندن پوزیشن فیوچرز در این adapter پشتیبانی نشده‌اند.

به همین علت `dry_run_mode=false` با خطای واضح رد می‌شود. هیچ مسیر ارسال سفارش، خصوصی یا اسپات، در موتور وجود ندارد. نمی‌توان این نسخه را آمادهٔ معامله با سرمایهٔ واقعی دانست. برای افزودن اجرای زنده، مستندات معتبر endpointهای خصوصی فیوچرز، سفارش و fill، بازیابی سفارش پس از timeout، تطبیق پوزیشن پس از restart و حفاظت سمت صرافی لازم است.

منابع بررسی:

- https://github.com/ccxt/ccxt/blob/master/python/ccxt/lbank.py
- https://github.com/ccxt/ccxt/wiki/ccxt-vs-lbank-api
- https://www.lbank.com/docs/contract.html

## اجرای سریع با Docker

در پوشهٔ پروژه:

```bash
cp .env.example .env
```

مقدار `BOT_PIN` در `.env` را با PIN دلخواه خود جایگزین کنید. سپس:

```bash
docker compose up -d --build
docker compose logs -f lbank-bot
```

داشبورد را در `http://localhost:8000` باز کنید و همان PIN را وارد کنید. پورت روی loopback میزبان تنظیم شده است.

حالت پیش‌فرض `PAPER_DATA_MODE=demo` کاملاً آفلاین است و **کندل و قیمت مصنوعی** تولید می‌کند. برچسب `demo` روی داشبورد نمایش داده می‌شود. نیازی به API Key نیست. سرمایهٔ اولیهٔ شبیه‌سازی با `PAPER_EQUITY` تعیین می‌شود؛ پیش‌فرض ۱۰٬۰۰۰ دلار است.

اولین اجرا کانفیگ پیش‌فرض را به `runtime/config.json` کپی می‌کند. پس از آن فایل داخل `runtime` مرجع اصلی است. تغییر `config.json` کنار کد، کانفیگ ذخیره‌شدهٔ اجرای Docker را تغییر نمی‌دهد. هر دو کانتینر پوشهٔ `runtime` را مشترک دارند تا `os.replace`، فایل‌های قفل و SQLite WAL درست کار کنند. Mount کردن تنها فایل کانفیگ با ذخیرهٔ اتمیک سازگار نیست.

برای توقف سرویس‌ها:

```bash
docker compose down
```

توقف سرویس، پوزیشن‌های شبیه‌سازی‌شده را از دیتابیس حذف نمی‌کند. برای بستن آن‌ها از داشبورد استفاده کنید. این بسته روی دادهٔ خالی شروع می‌شود و ابزار مهاجرت دیتابیس نسخه‌های دیگر ندارد.

## اجرا بدون Docker

Linux یا macOS و Python نسخهٔ ۳.۱۱ یا بالاتر لازم است. قفل‌ها از `fcntl` استفاده می‌کنند؛ روی Windows از Docker استفاده کنید.

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements-dev.txt
export BOT_PIN='my-personal-pin'
export PAPER_DATA_MODE=demo
python -u lbank_bot.py
```

در ترمینال دوم، در همان پوشه و با همان محیط مجازی:

```bash
source .venv/bin/activate
export BOT_PIN='my-personal-pin'
export PAPER_DATA_MODE=demo
uvicorn dashboard_server:app --host 127.0.0.1 --port 8000
```

در اجرای محلی، مسیر پیش‌فرض کانفیگ `config.json` و دیتابیس `data/lbank_ichimoku_bot.db` است. متغیرهای `BOT_CONFIG` و `BOT_DB` قابل تغییر هستند و باید برای دو پردازش یکسان باشند. اگر `BOT_PIN` محلی تنظیم نشود، مقدار درخواستی مشخصات، یعنی `1234`، استفاده می‌شود؛ در Docker تنظیم آن الزامی است.

## دادهٔ واقعی فیوچرز برای شبیه‌سازی

`PAPER_DATA_MODE=csv-lbank` قیمت عمومی قراردادهای LBank را می‌خواند، اما کندل‌ها باید از CSV فیوچرز تهیه‌شده توسط خودتان دریافت شوند. هیچ کندل اسپاتی به‌جای فیوچرز استفاده نمی‌شود. فایل مفقود، قدیمی، دارای gap یا نامعتبر باعث جلوگیری از سیگنال همان نماد و تلاش مجدد می‌شود.

در Docker فایل‌ها را در `runtime/ohlcv` بگذارید. در اجرای محلی پیش‌فرض `data/ohlcv` است و با `OHLCV_DIR` تغییر می‌کند. نام‌گذاری نمونه:

```text
BTC_USDT_USDT_1h.csv
BTC_USDT_USDT_4h.csv
ETH_USDT_USDT_1h.csv
ETH_USDT_USDT_4h.csv
```

برای هر نماد و هر تایم‌فریم مصرف‌شده، فایل باید با این ترتیب ستون‌ها موجود باشد:

```csv
timestamp,open,high,low,close,volume
```

`timestamp` زمان باز شدن کندل، با Unix milliseconds و مرزهای UTC است. ردیف‌ها باید صعودی، پیوسته و یکتا باشند. حداقل ۲۰۰ ردیف نگه دارید و آخرین ردیف را به کندل جاری اختصاص دهید؛ این ردیف طبق مشخصات همیشه حذف می‌شود. فایل‌ها باید مرتب به‌روزرسانی شوند تا آخرین کندل بسته‌شده با مرز زمانی فعلی مطابقت داشته باشد. تولیدکنندهٔ داده باید CSV را با فایل موقت و rename اتمیک جایگزین کند.

اگر داده یا قیمت قابل دریافت نباشد، خروج مربوط به آن نماد انجام نمی‌شود و ردیف پوزیشن حفظ می‌شود؛ این موضوع در پاسخ Panic و وضعیت نمایش داده می‌شود. این رفتار فقط شبیه‌سازی است و هیچ سفارش حفاظتی روی صرافی وجود ندارد.

## رفتار موتور

- فقط کندل‌های بسته‌شده برای Ichimoku، RSI، ATR، H2/L2، Barb Wire و کندل سیگنال مصرف می‌شوند. RSI و ATR با SMA اولیه و هموارسازی Wilder محاسبه می‌شوند.
- حالت MTF از روند HTF و ورود LTF استفاده می‌کند؛ حالت SINGLE از یک تایم‌فریم.
- اسکن اولیه پس از شروع و اسکن بعدی سه ثانیه بعد از مرز کندل انجام می‌شود. خطای داده پس از ده ثانیه دوباره امتحان می‌شود. کندل ارزیابی‌شده در دیتابیس ثبت می‌شود تا دوباره سیگنال ندهد.
- Watchdog و اسکنر جدا اجرا می‌شوند. عملیات تغییر پوزیشن در ربات و داشبورد با قفل مشترک بین پردازش‌ها انجام می‌شود. ثبت PnL و به‌روزرسانی یا حذف پوزیشن یک تراکنش SQLite است.
- سفارش در انتظار، انقضا، لغو، ورود، حد ضرر، TP1 و دنبال‌کردن Kijun پیاده‌سازی شده‌اند. حجم در Gap ورود دوباره کم می‌شود و TP1 با قیمت ورود جدید محاسبه می‌شود.
- حجم CCXT بر اساس تعداد قرارداد و `contractSize` محاسبه می‌شود. در DEMO مشخصات قرارداد شبیه‌سازی است و اندازهٔ حداقلی دقیق صرافی را بازنمایی نمی‌کند.
- اگر خروج جزئی یا باقی‌مانده زیر حداقل حجم باشد، کل پوزیشن در TP1 بسته می‌شود.
- خاموش‌کردن ورود خودکار، setupهای پرنشده را لغو می‌کند؛ مدیریت پوزیشن‌های باز ادامه دارد. Panic علاوه بر توقف ورود، همهٔ پوزیشن‌ها را برای بستن بررسی می‌کند.
- محدودیت زیان روزانه طبق فایل ورودی، بازهٔ شناور ۲۴ ساعت است. در زمان فعال‌شدن تریگر نیز دوباره بررسی می‌شود.
- کارمزد round-trip بین ارزش ورود و خروج تقسیم می‌شود. سود و زیان از مقدار پایه، قیمت ورود و خروج و کارمزد محاسبه می‌شود. Funding، لغزش، liquidation و تغییر قیمت طی فراخوانی API مدل نشده‌اند؛ خروج‌ها در آخرین قیمت مشاهده‌شده شبیه‌سازی می‌شوند.
- شمارندهٔ معاملات ۲۴ ساعت، تعداد خروج‌های ثبت‌شده است؛ TP1 و خروج باقی‌مانده دو رکورد هستند.
- سرمایهٔ اولیه در دیتابیس ذخیره می‌شود. تغییر بعدی `PAPER_EQUITY` سرمایهٔ همان دیتابیس را reset نمی‌کند.

جداول پایهٔ `positions` و `trade_history` دارای ستون‌های اضافی برای مشخصات قرارداد و حسابداری هستند. `scanned_candles` جلوگیری از تکرار سیگنال و `runtime` وضعیت پردازش‌ها را نگه می‌دارد.

## API و تست‌ها

همهٔ مسیرهای `/api/*` به هدر `X-Bot-Pin` نیاز دارند. صفحهٔ HTML بدون PIN باز می‌شود، اما اطلاعات حساب را بدون PIN دریافت نمی‌کند. مسیرها:

- `GET /api/status`
- `GET /api/config`
- `PUT /api/config`
- `POST /api/positions/close` با JSON شامل `symbol`
- `POST /api/positions/close-all` با JSON شامل `disable_auto_trade`

API کانفیگ `ETag` می‌دهد. ارسال آن با `If-Match` از بازنویسی تغییر هم‌زمان جلوگیری می‌کند؛ داشبورد این کار را انجام می‌دهد. مقادیر عددی، schema، تایم‌فریم‌ها و محدودهٔ ریسک ۰٫۱ تا ۵ درصد بررسی می‌شوند. PIN داخل مرورگر فقط در حافظه نگه داشته می‌شود.

```bash
python -m pytest tests -q
node tests/test_ui.cjs
```

تست Python، دو پردازش واقعی ربات و Uvicorn را در حالت DEMO راه‌اندازی و سپس متوقف می‌کند. هیچ سفارش واقعی ارسال نمی‌شود. تست JavaScript منطق DOM را بررسی می‌کند و جای تست بصری مرورگر را نمی‌گیرد. نتایج اجرا و محدودیت‌های بررسی در `TEST_REPORT.md` موجود است.

## تنظیمات پس از بنچمارک چهار خانواده

پیکربندی BTC مرحلهٔ قبل، در portfolio/prior/config.json نگه داشته شده است. مشخصات آن: DONCHIAN با SINGLE چهار‌ساعته و فقط BTC. ایچیموکو (9,26,52,26)، شکست Close بالاتر/پایین‌تر از کانال 20 کندل قبلی و بیرون Kumo؛ ورود بازار پس از بسته‌شدن. استاپ اولیه Kijun(26)، حداقل استاپ 1.2% با REJECT در سیگنال و fill واقعی، و تریل روی extreme مخالف 10 کندل بسته؛ بدون خروج جزئی، سربه‌سر یا هدف ثابت. RSI، ADX، Barb Wire و H2/L2 در این خانواده اعمال نمی‌شوند. مسیر چهار خانواده در strategy_archetypes.py تعریف شده است؛ این فایل باید کنار lbank_bot.py باشد.

112 پیکربندی در سه دوره اجرا شد؛ 17 ترکیب شرط حداقل 40 معامله و سود مثبت آموزش و دوره بعدی را گذراندند. برنده 288 معامله و $2,984.14 سود کل، $2,773.88 سود آموزش و $163.82 سود 2025–2026 داشت. دوره بعدی برای انتخاب استفاده شده و آزمون مستقل دست‌نخورده نیست. هیچ ترکیب واجدشرایط در محدوده 40–60 معامله یافت نشد. هدف فرکانس 25–60 معامله پنج‌ساله محقق نشد.

تنظیمات هر پوزیشن ساخته‌شده در نسخه جدید در SQLite ذخیره می‌شوند؛ تغییر config اندیکاتور، stop یا trail همین پوزیشن‌های ذخیره‌شده را عوض نمی‌کند. پوزیشن‌های قدیمی بدون snapshot فقط پارامترهای خروج و تایم‌فریمِ موجود در رکورد خود را حفظ می‌کنند؛ اندیکاتورهای ذخیره‌نشدهٔ قدیمی قابل استنتاج نیستند. سفارش شکست در خانواده‌های مربوط GTC است و با تغییر جهت رژیم یا برخورد استاپ سیگنال لغو می‌شود. مهاجرت پایگاه داده پوزیشن‌های قدیمی را حفظ می‌کند. حالت paper حفظ شده؛ PnL نمایشی ربات فقط کارمزد دارد. Funding و لغزش در بک‌تست اعمال شده‌اند. Funding چهار روز اول اکتبر آرشیوی نبود؛ برنده یک هزینه فرضی $0.37 دارد که در گزارش مشخص شده است.

## مدیریت مارجین و خروج قابل تنظیم Donchian

پیش‌فرض ارتقای سرمایه شامل پنج نماد BTC، ETH، SOL، XRP و ADA است. منطق
ورود همان Donchian20 + Kumo روی کندل بستهٔ ۴ ساعته با پریست crypto، استاپ
ATR2 و خروج CLOSE_TRAIL_KIJUN باقی می‌ماند. حداقل استاپ ۱٫۲٪ با REJECT
هم در سیگنال و هم در قیمت ورود بررسی می‌شود.

- `risk_and_exit.engaged_capital_pct=0.60`: سقف مارجین کل، نه هدف مصرف اجباری.
- `max_open_positions=4`: بودجه هر اسلات برابر equity × 0.60 / 4 است.
- `risk_per_trade_pct=0.005`: ریسک دلار از کل equity محاسبه می‌شود.
- `leverage_mode=DYNAMIC_MARGIN`: اهرم صحیح ۱ تا `default_isolated_leverage=5`
  از ceil(target_notional / slot_margin) تعیین می‌شود. در FIXED_LEVERAGE
  اهرم همیشه مقدار ثابت تنظیم‌شده است.
- حجم بر مبنای فاصله استاپ + کارمزد رفت‌وبرگشت ۰٫۱۲٪ + ذخیره لغزش ۰٫۰۴٪
  تعیین می‌شود. محدودیت مارجین و گرد کردن مقدار، ریسک را فقط کاهش می‌دهند.
  این ذخیره لغزش تضمین قیمت اجرای سفارش یا زیان دقیق در گپ بازار نیست.
- اهرم واقعی در دیتابیس هر پوزیشن ذخیره می‌شود؛ معاملات قدیمی در مهاجرت
  از اهرم کانفیگ ذخیره‌شدهٔ خود استفاده می‌کنند. رزرو سفارش‌های در انتظار
  نیز برای پذیرش معاملات جدید شمرده می‌شود.
- رسیدن PnL تحقق‌یافته خالص ۲۴ ساعت اخیر به زیان ۲٪ equity ورود جدید را
  متوقف می‌کند؛ خروج و مدیریت ریسک معاملات موجود ادامه دارد.

بخش `strategy_settings` مرجع تنظیمات Donchian است و کلیدهای قدیمی موتور
هنگام اعتبارسنجی از آن ساخته می‌شوند. `ichimoku_preset` دو مقدار crypto و
standard، `donchian_entry_period` دو مقدار ۲۰ و ۱۰ و `initial_stop_mode`
دو مقدار ATR2 و KIJUN را می‌پذیرند.

`exit_tp_mode` شامل STOP_TRAIL_DONCHIAN10 (استاپ پله‌ای کف/سقف ۱۰ کندل
بسته)، CLOSE_TRAIL_KIJUN (استاپ اولیه + خروج با کلوز نامطلوب کیجون) و
HYBRID_TRAIL_AND_HARD_TP است. در حالت ترکیبی، `hybrid_trail_mode` تریل
زیرین را انتخاب می‌کند و `hard_tp_rr` باید مثبت باشد. مقدار مثبت
`hard_tp_rr` در سایر حالت‌ها هم هدف قطعی را فعال می‌کند. صفر یعنی خاموش.
`breakeven_trigger_rr=0` پیش‌فرض خاموش است؛ مقدار ۲ استاپ را با رسیدن
قیمت به ۲R به ورود منتقل می‌کند، بدون خروج جزئی.

Hot-Reload برای ورودهای بعدی اعمال می‌شود؛ قواعد خروج، هدف، فاصله R و
تایم‌فریم معاملات باز تغییر نمی‌کنند. داشبورد مارجین درگیر واقعی، درصد
آن از equity و درصد مصرف بودجه مجاز را نشان می‌دهد و رزرو سفارش‌های
در انتظار را جداگانه نمایش می‌دهد. با خطای قیمت، درصدهای وابسته به equity
نامشخص نمایش داده می‌شوند، نه صفر ساختگی.

این تغییرات، تنظیمات اجرایی درخواستی‌اند؛ نتایج بک‌تست ذخیره‌شده مربوط
به پرتفوی شش‌نمادی و ریسک ۰٫۳۷۵٪ قبلی است و بازنویسی نشده است.
موتور فعلی همچنان paper-only است: حد سود، استاپ و اهرم در شبیه‌ساز
اجرا می‌شوند؛ اتصال فعلی CCXT امکان سفارش فیوچرز زنده و TP بومی LBank
را فراهم نمی‌کند.

## برندهٔ آزمون High-CAGR — 2026-10-06

پیش‌فرض فعلی از ماتریس ۳۸۴ ترکیبی انتخاب شد: سبد پنج‌نمادی، SINGLE 4h،
پریست standard، شکست Donchian10، استاپ ATR2 سیگنال با REJECT 1.2%،
تریل STOP_TRAIL_DONCHIAN10، ریسک ۰٫۷۵٪، چهار اسلات، مارجین مجاز ۶۰٪ و
اهرم FIXED_LEVERAGE=5. افزودن یک‌مرحله‌ای فعال است. CAGR کل ۳۲٫۲۴٪ و
DD کل ۳۴٫۵۶٪ بوده؛ هدف ۵۰–۱۰۰٪ با DD<=35% محقق نشد. انتخاب از گذشتهٔ
مشاهده‌شده است و ۲۰۲۵–۲۰۲۶ اعتبارسنجی دست‌نخورده محسوب نمی‌شود.

`initial_stop_anchor=SIGNAL` استاپ ATR2 را در خط ساخته‌شده از کندل سیگنال
نگه می‌دارد؛ ENTRY رفتار قبلیِ فاصلهٔ 2ATR از قیمت واقعی ورود را حفظ می‌کند.
در هر دو، فاصلهٔ کمتر از ۱٫۲٪ در زمان ورود رد می‌شود.

`pyramid_enabled=true` فقط با اهرم ثابت، تریل استاپ Donchian10 و بدون
TP قطعی/سربه‌سر مجاز است. پس از ۲R و پوشش هزینه توسط استاپ سودده،
شکست Donchian بعدی اجازهٔ تنها یک واحد با نصف ریسک را می‌دهد؛ میکرو‌استاپ
واحد جدید نیز رد می‌شود. استاپ دو واحد مشترک است و هیچ اسلات نمادی تازه‌ای
مصرف نمی‌شود. بودجهٔ مارجین کل همچنان محدودیت سخت ورود است. مارجین واحد
افزوده از بودجهٔ باقی‌مانده می‌آید؛ رسیدن به ریسک هدف تضمین نمی‌شود.

پوزیشن شبیه‌ساز با حجم مجموع و ورود میانگین نگه داشته می‌شود؛ اطلاعات
واحد افزوده در `scale_in_history` و ورود/R معاملهٔ پایه در ستون‌های root
ذخیره می‌شوند. ری‌استارت موجب افزودن دوباره نمی‌شود. تغییر تنظیمات خروج
در Hot-Reload افزودن به معاملات دارای قواعد قبلی را متوقف می‌کند و مدیریت
استاپ آن‌ها ادامه دارد. داشبورد R را بر مبنای معاملهٔ پایه نمایش می‌دهد.

گزارش و همهٔ آمار دوره‌ها در `high_cagr/output/report_high_cagr_fa.html`
و `matrix.json` هستند. موتور فعلی همچنان شبیه‌ساز polling است؛ کندل‌های
دقیقه‌ای، Funding و مسیر درون کندلِ بک‌تست به معنای اتصال زندهٔ آماده به
LBank نیستند. نتایج تاریخی قبلی بازنویسی نشده‌اند.

## اندازه‌گیری لغزش واقعی

در حالت `PAPER_DATA_MODE=csv-lbank` برای هر ورود، افزودن و خروج paper، دفتر سفارش زندهٔ LBank خوانده می‌شود و میانگین قیمتی که یک سفارش مارکت با همان حجم می‌گرفت در جدول `fill_quality` ثبت می‌شود. مقدار مثبت یعنی بدتر از قیمت paper. سود و زیان paper و مدیریت ریسک تغییر نمی‌کنند؛ خطا فقط ثبت می‌شود و معامله را متوقف نمی‌کند. بستن اضطراری اندازه‌گیری نمی‌شود. بک‌تست ۲bps برای هر fill فرض کرده است و کارت داشبورد میانه و P90 را با آن مقایسه می‌کند.

```bash
PAPER_DATA_MODE=csv-lbank python lbank_bot.py --probe-book BTC/USDT:USDT 0.01   # بررسی اولیه روی ماشین خودتان
FILL_QUALITY=off ...   # غیرفعال‌کردن اندازه‌گیری
```

این بخش فقط با دفتر سفارش ساختگی تست شده است؛ دسترسی به LBank از محیط توسعه ممکن نبود، پس دستور probe را یک‌بار خودتان اجرا کنید.

## فیلتر funding برای شورت (F4) — پیش‌فرض خاموش

نتیجهٔ دور سوم تحقیق (`high_cagr/output/r3/`): وقتی میانگین ۹ نرخ funding آخر (۳ روز) قبل از کندل ورود منفی است، یعنی شورت‌ها شلوغ‌اند و به لانگ‌ها پول می‌دهند، شورت جدید باز نمی‌شود. لانگ‌ها دست نمی‌خورند. روی ۱۰ نماد کاملاً تازه (HOLD2) همهٔ شرط‌های از پیش اعلام‌شده را پاس کرد.

- کلیدها در `strategy_settings`: `funding_short_filter_enabled` (پیش‌فرض false)، `funding_short_prints` (۹)، `funding_short_threshold` (۰).
- داده: فایل‌های `FUNDING_DIR/<symbol>_funding.csv` با ستون‌های `timestamp,funding_rate`. اسکریپت `fetch_funding.py` آن‌ها را می‌سازد. باید هر ساعت با cron اجرا شود:

```bash
FUNDING_DIR=data/funding python fetch_funding.py               # منبع LBank (ثبت نرخ هر تسویه؛ ۳ روز طول می‌کشد تا تاریخچه کامل شود)
FUNDING_DIR=data/funding python fetch_funding.py --source binance   # منبع تحقیق؛ از بعضی مناطق مسدود است
```

- اگر داده نباشد یا کهنه باشد (آخرین نرخ قدیمی‌تر از ۹ ساعت)، فیلتر چیزی را مسدود نمی‌کند و ربات مثل قبل رفتار می‌کند.
- تحقیق با funding بایننس انجام شده؛ funding لایبنک نزدیک است ولی یکسان نیست.

## فیلتر رژیم ATR (2A) و محافظ سود ۱R (5A)

**از ۷ اکتبر ۲۰۲۶ پیش‌فرض `config.json` همین 2A+5A است** (به درخواست مالک). V2، فیلتر BTC و افزودن امن 4B خاموش شده‌اند؛ ربات همچنان paper است. ثبت تغییر: `high_cagr/output/deployed_overrides.json`.

نتیجهٔ آزمون پنج ایده (`high_cagr/output/ideas/`): ترکیب 2A+5A روی پنج نماد اصلی، کل ۵ سال، CAGR ۴۱٫۳٪، DD ۲۱٫۱٪، Calmar 1.96 (baseline گزارش شکست: 32.2٪ / 34.6٪ / 0.93). این ترکیب پس از دیدن نتایج انتخاب شده و همان فیلتر ATR روی ۲۰ نماد دست‌نخوردهٔ قبلی (NEW10/HOLD10) بهبودی نداشت؛ پیش از پول واقعی روی HOLD2 و paper آزموده شود.

- 2A — کلیدها در `strategy_settings`: `atr_regime_filter_enabled`، `atr_regime_window` (۶۰)، `atr_regime_min_ratio` (۱٫۰). وقتی ATR آخرین کندل بستهٔ ۴ساعته از میانهٔ ATR شصت کندل قبلی کمتر است، نه ورود جدید باز می‌شود نه افزودن. هر ATR دقیقاً مثل اندیکاتور runtime روی پنجرهٔ خودش محاسبه می‌شود؛ ربات برای این کار `candle_fetch_limit + 60` کندل می‌خواند. تاریخچهٔ ناقص یا دارای gap یعنی ورود انجام نمی‌شود.
- 5A — همان profit floor موجود با `profit_floor_trigger_r=1.0` و `profit_floor_lock_r=0.1`.
- پیکربندی آزموده‌شدهٔ 2A+5A: `profit_floor_enabled=true`، `profit_floor_trigger_r=1.0`، `profit_floor_lock_r=0.1`، `safe_pyramid_enabled=false`، `pyramid_risk_fraction=0.5`، `stop_width_filter_enabled=false`، `btc_regime_filter_enabled=false`، `initial_stop_atr_mult=2.0`، `atr_regime_filter_enabled=true`، `atr_regime_window=60`، `atr_regime_min_ratio=1.0`؛ F4 خاموش. ترکیب 2A با V2، فیلتر BTC یا 4B آزموده نشده است.

## بخش دوم: C3 (پولبک در روند ۴ساعته) روی ۱۰ ارز دیگر — فقط paper

C3 جزء خود ربات است: `python lbank_bot.py` (و سرویس `lbank-bot` در Docker) آن را در یک thread جدا با تنظیمات `c3_config.json` و دیتابیس جدا (`data/c3_sleeve.db` یا `runtime/c3_sleeve.db` در Docker) اجرا می‌کند. استراتژی و تنظیمات ربات اصلی دست نمی‌خورند و خطای C3 ربات را متوقف نمی‌کند. اندازهٔ پوزیشن‌های C3 از سرمایهٔ مشترک حساب می‌شود (سرمایهٔ paper ربات + سود/زیان بسته‌شدهٔ C3). **کنترل از همان داشبورد:** در پنل «استراتژی دوم: C3+D» می‌توانید ورود جدید را روشن/خاموش کنید، ریسک، سقف نُوشنال، تأیید ورود D، فیلتر آخر هفته و فهرست نمادها را عوض کنید (یا JSON کامل را ویرایش کنید)، پوزیشن‌ها و ۲۰ معاملهٔ اخیر را ببینید و هر پوزیشن را آنی ببندید. ذخیرهٔ تنظیمات بدون ری‌استارت در چند ثانیه اعمال می‌شود؛ فقط حالت paper پذیرفته می‌شود (`dry_run_mode` اجباری true). دکمهٔ «بستن اضطراری» هر دو استراتژی را می‌بندد و ورود جدید هر دو را متوقف می‌کند. خاموش کردن کامل thread: متغیر محیطی `C3_IN_BOT=0`. سرویس dashboard در Docker هم `C3_CONFIG` و `C3_DB` را دارد.

- **قواعد (کندل بستهٔ ۴ساعته):** لانگ وقتی EMA50 بالای EMA200 است و RSI14 از ۴۰ به بالا عبور می‌کند؛ شورت برعکس (EMA50 زیر EMA200، RSI از ۶۰ به پایین). کندل سیگنالی که شنبه/یکشنبه (UTC) بسته شود معامله نمی‌شود. استاپ اولیه ۲ ATR، سپس تریل: بهترین Close منهای ۴٫۵ ATR که فقط جلو می‌رود.
- **ارزها:** AAVE، UNI، AVAX، KSM، EGLD، DOT، DOGE، ONE، TRX، SUSHI (۱۰ ارز برتر بر اساس سود C3 در دورهٔ Train میان ۳۰ ارز آزموده‌شده). باید پیش از اجرا بررسی شود که قرارداد USDT دائمی همهٔ آن‌ها در LBank فعال است؛ نماد ناموجود فقط خطا ثبت می‌کند.
- **ریسک:** ۰٫۲٪ سرمایه در هر معامله (ربات ۰٫۷۵٪ + C3+D ‏۰٫۲٪ = بهترین ترکیب با شرط افت Train ≤ ۲۰٪ در `high_cagr/output/ideas/risk_sweep/`: بک‌تست CAGR ۶۶٪ / افت ۲۰٪). فایل runtime قدیمی که هنوز ۰٫۱۵٪ پیش‌فرض را دارد خودکار به ۰٫۲٪ ارتقا می‌یابد و کلیدهای جدید (مثل `confirm_bars`) به آن اضافه می‌شوند؛ مقداری که خودتان عوض کرده‌اید دست نمی‌خورد، سقف نُوشنال ۴۰٪ برای هر پوزیشن، `dry_run_mode` اجباری true.
- **شواهد:** روی ۲۰ ارز کاملاً دست‌نخورده CAGR ۲۱٪ با افت ۳۸٪ (Calmar Train/Validation ‏0.61/0.51) و ۱۹ از ۲۰ ارز سودده؛ همبستگی با ربات اصلی حدود ۰٫۲۵ تا ۰٫۳۵. نتیجهٔ ترکیبی بک‌تست (ربات + C3 با ۰٫۲۵٪) خوش‌بینانه است، چون ارزها با نگاه به سود انتخاب شده‌اند.
- **اجرای جداگانه (اختیاری):** `PAPER_DATA_MODE=csv-lbank python c3_sleeve.py` (فایل‌های CSV فیوچرز ۴ساعتهٔ این ۱۰ ارز در `OHLCV_DIR` لازم است؛ حداقل ۱۰۰۰ کندل برای گرم شدن EMA200). در حالت عادی لازم نیست؛ ربات خودش C3 را اجرا می‌کند. اجرای جداگانه فقط با `C3_IN_BOT=0` روی ربات (وگرنه C3 دوبار اجرا می‌شود).
- **تأیید ورود (نسخهٔ D، پیش‌فرض):** `confirm_bars: 3` — بعد از سیگنال پولبک، ورود فقط وقتی انجام می‌شود که تا ۳ کندل بعد، بستهٔ کندلی از بستهٔ کندل سیگنال فراتر برود (برای شورت پایین‌تر) و روند EMA50/200 برنگشته باشد؛ ورود در قیمت بعد از کندل تأییدکننده و استاپ ۲ATR همان کندل. کندل تأیید هم نباید در آخر هفته بسته شود. سیگنال‌های در انتظار در جدول `pending` ذخیره می‌شوند. مقدار ۰ = C3 قدیمی. بک‌تست ۱۰ ارز (ریسک ۰٫۵٪): CAGR ۴۷٫۵٪ / افت ۲۷٫۴٪ با Calmar Train/Valid ‏1.85/2.28، در برابر CAGR ۵۲٫۴٪ / افت ۳۸٫۲٪ و Calmar ‏1.38/2.15 بدون تأیید (سود کمی کمتر، افت خیلی کمتر).
- **تست‌ها:** `tests/test_c3_sleeve.py` سیگنال و ATR را روی دادهٔ واقعی با موتور بک‌تست مقایسه می‌کند (یکسان) و چرخهٔ ورود/تریل/استاپ را می‌آزماید؛ ورودهای تأییدشدهٔ D هم کندل‌به‌کندل با بک‌تست یکسان‌اند.
