# گزارش پیاده‌سازی TITANIUM IRIS

## تغییرات

هویت بصری Trade با پالت دقیق Obsidian Terminal و Titanium Frost پیاده‌سازی شد. ظاهر پیش‌فرض تیره است؛ انتخاب روشن و هماهنگ با سیستم در سربرگ صفحات عمومی، پنل مشتری و مدیریت در دسترس است. نام و هندسهٔ نشان Trade حفظ شده و آیکن‌های نصب برنامه فقط با پالت جدید بازتولید شده‌اند.

اجزای موجود شامل کارت‌ها، فرم‌ها، جدول‌ها، قیمت‌گذاری، سفارش‌ها، اعلان‌ها، دیالوگ‌ها، حالت‌های انتخاب و غیرفعال، صفحهٔ آفلاین و ترمینال مستقل هماهنگ شدند. دادهٔ بک‌تست، APIها، احراز هویت، تنظیمات ربات‌ها، اجرای معامله و قواعد مالی تغییر نکرده‌اند. وابستگی جدیدی به برنامه اضافه نشده است.

## معماری توکن‌ها

منبع واحد رنگ‌ها `public/portal-assets/titanium.css` است؛ `app/globals.css` آن را در خروجی Next.js وارد می‌کند و ترمینال مستقل همان فایل را در HTML خود قرار می‌دهد. بستهٔ مشتری و Docker نیز این فایل و کنترل‌کنندهٔ ظاهر را همراه برنامه حمل می‌کنند.

- ۱۲ رنگ پایه برای هر تم عیناً مطابق درخواست هستند؛ تست مستقل مانع تغییر تصادفی آن‌ها می‌شود.
- توکن‌های معنایی سطح، متن، دکمه، ورودی، مرز، تمرکز، هشدار، خطا، موفقیت، سایه، انتخاب، skeleton و نمودار از پالت پایه مشتق می‌شوند.
- نام‌های قدیمی مانند `--accent` و `--good` صرفاً به نقش‌های جدید ارجاع می‌دهند؛ رنگ مستقل دیگری تعریف نمی‌کنند.
- در تم روشن، `--profit-text` و `--premium-text` نسخه‌های تیره‌تر برای متن کوچک روی سطوح برجسته هستند؛ رنگ‌های اصلی `--profit` و `--premium-accent` ثابت مانده‌اند. مرز ورودی‌ها نیز برای وضوح کنترل‌ها تقویت شده است.
- سود و زیان به‌ترتیب فیروزه‌ای و صورتی‌اند. متن PnL علامت و برچسب دسترس‌پذیر دارد، دقت مقدار منبع حفظ می‌شود و اعداد از ارقام هم‌عرض استفاده می‌کنند. جهت خرید/فروش علاوه بر رنگ، با متن مشخص می‌شود.
- SVG هیرو از توکن‌های خط، گرادیان، شبکه، محور، مکان‌نما و نشانگر استفاده می‌کند. Chart.js از همان پالت برای سرمایه، DD، میله‌های سود/زیان، تحلیل F، محور، راهنما و tooltip استفاده می‌کند؛ با تغییر تم، نمودارهای موجود از همان دادهٔ حافظه دوباره رسم می‌شوند و درخواست مالی جدیدی ارسال نمی‌شود.

## تغییر ظاهر

`appearance.js` یک کنترل‌کنندهٔ مشترک و هم‌زمان پیش از نمایش صفحه است. تنها مقدار غیرحساس `dark | light | system` با کلید `trade.appearance` در localStorage ذخیره می‌شود. انتخاب سیستم با `matchMedia` زنده دنبال می‌شود و رویداد storage انتخاب را بین تب‌ها هماهنگ می‌کند. مسدودبودن storage باعث خرابی رابط نمی‌شود.

اسکریپت در head خروجی ثابت Next.js، پیش از hydration اجرا می‌شود؛ پالت از شروع بارگذاری اعمال می‌شود. `ThemeProvider` با `useSyncExternalStore` به کنترل‌کننده وصل است و snapshot سمت سرور ثابت می‌ماند. سیاست CSP موجود، هش همین اسکریپت ثابت را محاسبه می‌کند؛ مجوز unsafe-inline یا eval اضافه نشده است.

Service Worker فقط سه فایل عمومی صفحهٔ آفلاین، CSS توکن‌ها و کنترل‌کنندهٔ ظاهر را cache می‌کند؛ دادهٔ مالی، صفحهٔ خصوصی و پاسخ API cache نمی‌شوند.

## صفحات بررسی‌شده

| بخش | بررسی |
| --- | --- |
| صفحهٔ اصلی و بک‌تست | هر دو تم، حرکت/توقف هیرو، reduced motion، جدول سالانه و مسیرهای ثبت‌نام/ورود |
| ثبت‌نام و ورود | هر دو تم، فرم‌ها و نمایش خطا |
| پنل مشتری | هر دو تم، محصول سیگنال/معاملهٔ خودکار، سرمایه و مدت، قیمت‌ها، سفارش و دیالوگ خرید |
| حساب و ربات‌ها | اتصال آزمایشی، پاک‌شدن اطلاعات ورودی حساس، جدول‌ها، وضعیت لایسنس و آفلاین |
| کارتابل مدیر | هر دو تم، کاربران، قیمت‌گذاری، سفارش‌ها، تأیید/رد، دیالوگ‌ها و گزارش رویداد |
| ترمینال مستقل | نمای کلی، پوزیشن‌ها، عملکرد، F و تنظیمات؛ هر دو تم و نمودار واقعی Chart.js |
| رفتار ظاهر | ماندگاری پس از refresh، تغییر سیستم، همگام‌شدن تب‌ها، storage مسدود، اجرای پالت بدون hydration |

عرض‌های ۳۲۰، ۳۶۰، ۳۹۰، ۷۶۸ و ۱۴۴۰ پیکسل بسته به سناریو بررسی شدند. سرریز افقی ترمینال قدیمی در عرض ۳۲۰ رفع شد. تست کنتراست مرورگر حداقل ۴٫۵:۱ را برای متن‌های کلیدی و حداقل ۳:۱ را برای مرز ورودی‌ها بررسی می‌کند؛ این آزمون، ممیزی جامع تمام الزامات WCAG نیست.

## اعتبارسنجی

| بررسی | نتیجه |
| --- | --- |
| `npm --prefix frontend run build` | موفق؛ خروجی ثابت تمام مسیرهای Next.js |
| `npm --prefix frontend run typecheck` | موفق |
| `npm --prefix frontend test` | ۸ تست موفق: API/session، ظاهر، پالت دقیق و نمایش PnL |
| `python -m pytest -q` با متغیرهای مرورگر | ۶۶۷ موفق، ۲۱ skipped؛ شامل ۱۰ سناریوی مرورگر |
| بررسی قالب فایل‌های TSX/CSS/JS تغییرکرده با Prettier 3.8.1 | موفق |
| `git diff --check` | موفق |
| lint | فرمان lint در پروژه تعریف نشده است |

pytest یک هشدار deprecation موجود مربوط به Starlette/httpx دارد. skipped به معنای تست اجرا‌نشده است، نه خطای تست. آزمون مستقل قدیمی DOM مطابق بخش محدودیت‌ها همچنان خطای پیشین را دارد.

برای تکرار آزمون نمودار، نسخهٔ موجود Chart.js 4.4.1 UMD را در فایلی محلی قرار دهید و `PORTAL_TEST_CHART_JS` را به آن مسیر تنظیم کنید. این مسیر فقط برای آزمون مرورگر است؛ فایل کتابخانه یا دادهٔ آزمایشی به برنامه اضافه نشده است. `PORTAL_SCREENSHOTS` مسیر اختیاری تصاویر آزمون‌هاست.

## محدودیت‌ها

- مرورگر واقعی آزمون‌شده Chromium است؛ Safari و Firefox در این محیط اجرا نشده‌اند.
- پروژه فرمان یا پیکربندی ESLint ندارد؛ بررسی قالب با Prettier و بررسی نوع با TypeScript انجام شده است.
- آزمون قدیمی `node tests/test_ui.cjs` پیش از این تغییرات هم به‌علت نداشتن `document.querySelectorAll` در DOM شبیه‌سازی‌شده خطا می‌دهد. همان خطا با فایل `dashboard_server.py` نسخهٔ HEAD قبلی بازتولید شد؛ این تست قدیمی بازنویسی نشده است. سناریوهای واقعی مرورگر و pytest جداگانه اجرا شدند.
- بارگیری CDN فعلی Chart.js در این محیط محدود بود؛ آزمون نمودار واقعی با همان نسخهٔ کتابخانه از یک فایل محلی انجام شد. آدرس و نسخهٔ CDN برنامه تغییر نکرده‌اند.
- بخش‌های ناموجود مانند order book، کندل و کیف پول جدید ساخته نشدند؛ توکن‌های مربوط به صعود/نزول، حجم و اندیکاتورها برای استفادهٔ موجود/آتی آماده‌اند. هیچ قابلیت یا سیگنال AI جدیدی اضافه نشده است.
- تغییری منتشر یا deploy نشده است؛ این کار فقط کد و پیش‌نویس رابط را آماده می‌کند.
