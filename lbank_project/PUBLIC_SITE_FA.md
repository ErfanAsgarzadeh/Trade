# راه‌اندازی سایت فروش، پنل مشتری و کارتابل مدیر (PostgreSQL)

سایت (`/`)، پنل مشتری (`/dashboard/`) و کارتابل مدیر (`/admin/`) با `portal-postgres-compose.yml` اجرا می‌شوند:
پایگاه دادهٔ PostgreSQL 17 (بدون پورت عمومی)، وب و worker خواندن حساب‌ها. این یک پروژهٔ Docker جداست و به ربات‌ها
دست نمی‌زند. `portal-owner-compose.yml` runtime ربات‌های مالک را فقط‌خواندنی به وب می‌دهد.
`portal-public-compose.yml` (وقتی دامنه داشتید) Caddy را جلوی سایت می‌گذارد و HTTPS را خودکار می‌گیرد.

## یک‌بار: رازها
```bash
cd /opt/Trade/lbank_project
mkdir -p issuer-keys && chmod 700 issuer-keys
docker compose -f portal-postgres-compose.yml build portal
docker run --rm -v "$PWD/issuer-keys:/app/issuer-keys" trade-portal-central-portal python portal_setup.py
chmod 644 issuer-keys/postgres_password
```
PostgreSQL فایل رمز را با کاربر خودش (نه root) می‌خواند، پس آن فایل باید قابل‌خواندن باشد؛ پوشهٔ `issuer-keys` با ۷۰۰ برای بقیهٔ کاربران سرور بسته می‌ماند.
`portal_setup.py` رمز پایگاه داده، آدرس اتصال و کلید رمزگذاری (`portal.key`) را در `issuer-keys/` می‌سازد و چاپ نمی‌کند.
از کل پوشهٔ `issuer-keys/` و از دادهٔ پایگاه داده جداگانه پشتیبان بگیرید.

## بدون دامنه (فقط برای مالک، از طریق تونل SSH)
```bash
PORTAL_ALLOW_LOCAL_HTTP=1 docker compose -f portal-postgres-compose.yml -f portal-owner-compose.yml up -d
```
روی کامپیوتر خودتان: `ssh -L 8080:127.0.0.1:8080 root@IP_SERVER` و بعد `http://127.0.0.1:8080`.

## با دامنه (عمومی، HTTPS)
```bash
PORTAL_DOMAIN=example.com docker compose -f portal-postgres-compose.yml -f portal-owner-compose.yml -f portal-public-compose.yml up -d
```

## حساب مالک، نقش مدیر و ربات‌های مالک
در سایت ثبت‌نام کنید، بعد:
```bash
C="docker compose -f portal-postgres-compose.yml -f portal-owner-compose.yml"
$C exec portal python portal_admin.py set-admin USERNAME
echo '{"customer_id": "USERNAME"}' > runtime/customer_identity.json
echo '{"main": "paper-live-lbank/shahin.db", "c3": "paper-live-lbank/mojsavar.db", "pa": "paper-live-lbank/ghoghnous.db"}' > runtime/portal_runtime.json
$C exec portal python portal_admin.py bind-runtime USERNAME /app/owner-runtime
```

## پشتیبان پایگاه داده
```bash
docker compose -f portal-postgres-compose.yml exec -T db pg_dump -U trade_portal trade_portal | gzip > /root/portal-$(date +%Y%m%d).sql.gz
```

فروش هر دو محصول تا ثبت قیمت و بازکردن صریح در کارتابل بسته می‌ماند.

## سئو و ثبت سایت در موتورهای جست‌وجو

سایت این موارد را خودش می‌سازد و همه از `PORTAL_ORIGIN` خوانده می‌شوند، پس بعد از تنظیم دامنه کار دیگری لازم نیست:

- `/robots.txt` و `/sitemap.xml` (شامل همهٔ مقاله‌های بلاگ)
- خبرخوان بلاگ در `/blog/rss.xml`
- تگ canonical، تصویر اشتراک‌گذاری (`og-image.png`) و دادهٔ ساختاریافته (Organization، WebSite، SoftwareApplication، FAQPage)
- پنل کاربر، پنل مدیریت و API با `X-Robots-Tag: noindex` از نتایج جست‌وجو بیرون می‌مانند.

بعد از بالا آمدن سایت روی دامنه:

1. دامنه را در [Google Search Console](https://search.google.com/search-console) ثبت و با رکورد DNS تأیید کنید.
2. آدرس `https://دامنه/sitemap.xml` را در بخش Sitemaps بفرستید.
3. همین کار را در [Bing Webmaster Tools](https://www.bing.com/webmasters) انجام دهید.

مقاله‌های بلاگ از «پنل مدیریت ← بلاگ» نوشته و منتشر می‌شوند و نیازی به build دوباره ندارند. مقاله‌ها در دیتابیس ذخیره می‌شوند؛ پشتیبان دیتابیس، مقاله‌ها را هم نگه می‌دارد.

رتبهٔ اول را هیچ تنظیم فنی‌ای تضمین نمی‌کند. بعد از این مرحله، رتبه به محتوای تازه (مقاله و راهنما)، لینک از سایت‌های معتبر و سابقهٔ دامنه بستگی دارد.

## پرداخت با USDT و USDC (Trust Wallet)

مشتری بعد از ثبت درخواست اشتراک، روش پرداخت را انتخاب می‌کند: USDT روی TRON (TRC20)، یا USDT و USDC روی BNB Smart Chain (BEP20).
هر فاکتور یک مبلغ یکتا دارد (قیمت به‌علاوهٔ چند هزارم دلار)، پس واریز دقیقاً همان مبلغ به آدرس شما، سفارش را مشخص می‌کند و
مشتری لازم نیست هش تراکنش وارد کند. پرداخت از سه راه انجام می‌شود:

- **اتصال Trust Wallet:** اگر افزونهٔ Trust Wallet روی مرورگر باشد (یا صفحه داخل مرورگر خود Trust Wallet باز شده باشد)، دکمهٔ «اتصال و پرداخت با Trust Wallet» کیف پول را وصل می‌کند، شبکه را روی BNB Smart Chain می‌برد و مبلغ و آدرس را آمادهٔ تأیید می‌کند.
- **دکمهٔ «پرداخت در اپ Trust Wallet»:** روی گوشی، اپ را با مبلغ، توکن و آدرس پرشده باز می‌کند.
- **کد QR:** روی کامپیوتر، با دوربین گوشی اسکن می‌شود و همان صفحهٔ پرداخت Trust Wallet را باز می‌کند.

### راه‌اندازی
1. در Trust Wallet: Receive، سپس USDT روی TRON و USDT روی BNB Smart Chain را انتخاب کنید و آدرس‌ها را کپی کنید.
2. پنل مدیریت ← «پرداخت»: آدرس‌ها را وارد و ذخیره کنید. سایت فقط آدرس عمومی را لازم دارد؛ **عبارت بازیابی (seed) یا کلید خصوصی را هرگز جایی وارد نکنید.**
3. سرویس `payment-worker` همراه بقیهٔ سرویس‌ها با `docker compose ... up -d` بالا می‌آید و هر ۲۰ ثانیه شبکه را بررسی می‌کند. زمان آخرین بررسی موفق در همان صفحه دیده می‌شود.
4. اگر گزینهٔ «فعال‌سازی خودکار سیگنال» روشن باشد، اشتراک سیگنال بعد از تأیید پرداخت خودکار به صف صدور لایسنس می‌رود (سرویس صدور باید روشن باشد). معاملهٔ خودکار همیشه بعد از بررسی حساب صرافی توسط شما تأیید می‌شود؛ شناسهٔ پرداخت در فرم تأیید خودکار پر می‌شود.

### نکته‌ها
- پرداخت TRON بعد از تأیید نهایی شبکه و پرداخت BNB بعد از ۱۵ بلاک (حدود ۱۵ ثانیه) ثبت می‌شود.
- پرداختی که دیرتر از مهلت فاکتور برسد تا ۲۴ ساعت هنوز به سفارش وصل می‌شود.
- واریزی که مبلغ یا شبکه‌اش با هیچ فاکتوری جور نباشد در «واریزهای دریافتی» با وضعیت «بدون فاکتور» دیده می‌شود؛ آن را دستی بررسی و از کارتابل درخواست‌ها با همان شناسه تأیید کنید.
- برای خواندن شبکه از سرویس‌های عمومی `api.trongrid.io` و `bsc-rpc.publicnode.com` استفاده می‌شود؛ سرور باید به اینترنت دسترسی داشته باشد.

## ربات تلگرام کاربران

1. در تلگرام به ‎@BotFather‎ پیام بدهید، دستور ‎/newbot‎ را بزنید، یک نام و یک نام کاربری که به ‎bot‎ ختم شود انتخاب کنید و توکن را بگیرید.
2. در کارتابل مدیریت، تب «تلگرام»، توکن را وارد و «ذخیره و اتصال ربات» را بزنید. توکن رمزنگاری‌شده ذخیره می‌شود و دیگر نمایش داده نمی‌شود.
3. سرویس ‎telegram-worker‎ همراه بقیهٔ سرویس‌ها با Docker اجرا می‌شود؛ به دامنه یا وبهوک نیازی نیست (long polling).
4. کاربران از «اطلاعات کاربری» دکمهٔ «اتصال به تلگرام» را می‌زنند؛ لینک یک‌بارمصرف ربات باز می‌شود و با Start حساب وصل می‌شود. هر کاربر می‌تواند ارسال سیگنال یا اطلاع‌رسانی را خاموش کند یا اتصال را قطع کند (‎/stop‎ در ربات هم همین کار را می‌کند).

چه پیام‌هایی ارسال می‌شود: سیگنال ربات‌ها (فقط برای اشتراک فعال)، تأیید پرداخت، فعال‌شدن اشتراک و پیام همگانی مدیر.

اگر سرور در ایران است، ‎api.telegram.org‎ فیلتر است؛ یک پراکسی HTTPS در فایل ‎.env‎ تعریف کنید:

```
TELEGRAM_HTTPS_PROXY=http://proxy-host:port
```

## دعوت دوستان و برنامه‌های رفرال

هر کاربر در پنل خود بخش «دعوت دوستان» را دارد: کد دعوت، لینک آماده (`/register/?ref=CODE`)، دکمه‌های اشتراک در تلگرام، واتس‌اپ و X، آمار دعوت‌ها، اعتبار و کوپن‌ها. کد را می‌توان تا ۴ بار به کد دلخواه تغییر داد و لینک‌های قبلی همچنان کار می‌کنند.

راه‌اندازی در کارتابل مدیریت، تب «دعوت و پاداش»:

1. «سیستم دعوت فعال باشد» را بزنید و ذخیره کنید.
2. از یکی از الگوها (تخفیف دوطرفه، تخفیف دوست + اعتبار دعوت‌کننده، کمیسیون همکاری در فروش، پاداش پلکانی، کمپین تخفیف) یا «برنامهٔ دلخواه» برنامه بسازید و «پیش‌فرض» را روشن کنید.

هر برنامه دو بخش دارد:

- **تخفیف دوستِ دعوت‌شده:** درصدی یا مبلغ ثابت، تعداد خریدهای مشمول، مهلت پس از ثبت‌نام، حداقل مبلغ و محصول.
- **پاداش دعوت‌کننده:**
  - نوع پاداش: اعتبار ثابت، کمیسیون درصدی از مبلغ پرداختی دوست، یا کوپن درصدی.
  - برای چه خریدی: فقط اولین خرید هر دوست، یا هر خرید با سقف.
  - دورهٔ انتظار، تاریخ انقضا و سقف کل.
  - پله‌های پاداش بر اساس تعداد دوستان خریدار.

کدهای ویژه: برای اینفلوئنسر یا همکار، کد اختصاصی با صاحب و برنامهٔ جدا بسازید. برای کمپین عمومی (مثلاً NOWRUZ) صاحب را خالی بگذارید. سقف تعداد استفاده و غیرفعال‌کردن هم دارد.

قواعد:

- پاداش فقط بعد از تأیید خرید دوست ثبت می‌شود.
- استفاده از کد خود یا کد کسی که شما دعوتش کرده‌اید ممکن نیست.
- کد را فقط هنگام ثبت‌نام یا تا چند روز بعد از آن (قابل تنظیم) و پیش از اولین خرید می‌توان وارد کرد.
- اعتبار و کوپن خودکار در خرید بعدی کم می‌شود. اگر سفارش لغو یا رد شود، برمی‌گردد.
- اگر اعتبار کل مبلغ را پوشش دهد، پرداختی لازم نیست. سفارش سیگنال با تأیید خودکار فعال می‌شود و سفارش معاملهٔ خودکار با شناسهٔ `credit-…` در کارتابل تأیید می‌شود.
- غیرفعال‌کردن یک برنامه، تخفیف‌ها و پاداش‌های بعدی آن را متوقف می‌کند. اعتبارهایی که قبلاً داده شده باقی می‌مانند.

مدیر می‌تواند به هر کاربر اعتبار یا کوپن دستی بدهد و هر پاداش را باطل کند. همهٔ این کارها در سوابق عملیات ثبت می‌شود.
