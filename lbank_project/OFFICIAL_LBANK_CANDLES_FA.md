# Paper با تاریخچه و کندل Futures خود LBank

این مسیر فقط دادهٔ عمومی می‌خواند؛ هیچ سفارش واقعی ثبت نمی‌کند. آداپتور از
همان route نمودار Futures وب LBank استفاده می‌کند:
`https://uuapi.lbank.com/cfd/query/v1.0/KLinelst`، با `type=4h`،
`instrumentID=BTCUSDT` و `exchangeID=Exchange`. این endpoint در SDK رسمی
OpenAPI مستند نشده و پایداری آن تضمین نشده است. مبنای شناسایی، کد منتشرشدهٔ
خود سایت LBank در صفحهٔ Futures است، نه حدس‌زدن endpoint یک صرافی دیگر.

## وضعیت بررسی

در ۲۰۲۶-۱۰-۱۶ هر ۳۵ نماد تنظیمات جاری پاسخ ۱۰۰۰ ردیفی دادند؛ برای KSM و XRP
یک ردیف باز حذف شد و ۹۹۹ ردیف بسته باقی ماند. آخرین ۸۰۰ کندل تمام نمادها
پیوسته، دارای OHLCV معتبر و شامل آخرین کندل بسته‌شده بودند. سپس parser جدید
تمام ۹۹۹/۱۰۰۰ کندل بستهٔ هر ۳۵ نماد را با موفقیت بررسی کرد. گزارش ثبت‌شده:
`reports/lbank_official_history_audit_20261016.json`.
این نتیجهٔ همان زمان دریافت است؛ دستور bootstrap باید روی سرور شما دوباره
اجرا شود تا تازگی دادهٔ زمان شروع شما تأیید شود.

اعتبارسنجی کد: مجموعهٔ Python شامل ۳۷۵ تست موفق و ۲۰ skipped بود؛ موارد skip
به دادهٔ پژوهشی و PostgreSQL موقت وابسته‌اند. مصرف همین دادهٔ واقعی در محاسبات
اندیکاتورهای هر سه موتور (۵+۱۰+۲۰ نماد) و یک دور دریافت زندهٔ collector برای
BTC نیز موفق بود. این آزمون ساخت Docker روی سرور شما یا ثبت سفارش واقعی نیست.

اطلاعات بسته از uppercase/lowercase شناخته‌شدهٔ LBank خوانده می‌شود. هویت
نماد، صرافی، دوره، مرز UTC، پیوستگی، ترتیب، یکتایی، هندسهٔ OHLC و اعداد متناهی
کنترل می‌شوند. کندل باز مصرف نمی‌شود؛ high/low تغییر نمی‌کند، gap ساخته یا
پر نمی‌شود، و Spot/Binance fallback وجود ندارد. حجم همان Volume گزارش‌شدهٔ
API است؛ تبدیل واحدِ تأییدنشده روی آن انجام نمی‌شود.

مسیر رسمی جداست: `runtime/ohlcv/official/`. فایل‌های نمونه‌برداری قبلی در
`runtime/ohlcv/` تغییر نمی‌کنند. فایل JSON کنار هر CSV، منبع، زمان دریافت و
SHA256 محتوا را نگه می‌دارد. انتشار با rename اتمیک است؛ عدم تطابق receipt/CSV
باعث رد موقت داده می‌شود. این receipt گواهی امضاشدهٔ صرافی نیست.

## نصب روی سرور موجود

قبل از تغییر، موتور و داشبورد و collector را متوقف و از کل runtime و .env
پشتیبان سازگار بگیرید. تنظیمات استراتژی و PIN موجود حفظ می‌شوند. در .env:

```env
PAPER_DATA_MODE=csv-lbank
LBANK_OFFICIAL_CANDLES=1
BOT_DB_PATH=/app/runtime/paper-live-lbank/shahin.db
C3_DB_PATH=/app/runtime/paper-live-lbank/mojsavar.db
PA_DB_PATH=/app/runtime/paper-live-lbank/ghoghnous.db
```

سه مسیر تازه، حساب Paper واقعی‌داده را از حساب demo قبلی جدا می‌کند؛ فایل‌های
قبلی پاک نمی‌شوند. اگر قبلاً همین مسیر تازه را استفاده کرده‌اید، نام جدیدی
انتخاب کنید؛ تغییر PAPER_EQUITY سرمایهٔ دیتابیس موجود را reset نمی‌کند.
برای مشاهدهٔ موجودی یا دریافت این کندل‌ها API Key خصوصی لازم نیست.

پس از دریافت همین نسخهٔ سورس و ساخت ایمیج جدید:

```bash
docker compose --progress plain build
docker compose run --rm --no-deps lbank-candles python -u lbank_candles.py --once
```

فقط اگر خروجی `Official Futures history: 35/35 symbols ready` و exit code صفر
بود، collector را اجرا کنید و سپس هر سه ربات را با موتور اصلی روشن کنید:

```bash
docker compose up -d --force-recreate lbank-candles lbank-dashboard lbank-bot
docker compose logs --since=2m --tail=80 lbank-candles lbank-bot
```

collector با دو درخواست هم‌زمان، هر دور ۱۰۰۰ ردیف هر نماد را می‌گیرد و بین
دورها ۶۰ ثانیه مکث می‌کند. یک دور خودش زمان می‌برد؛ دورهٔ کامل دقیقاً ۶۰ ثانیه
نیست. در خطای API فایل معتبر قبلی جایگزین نمی‌شود. موتور receipt قدیمی‌تر از
۶۰۰ ثانیه، دادهٔ آینده یا نبود آخرین کندل بسته‌شده را رد می‌کند. مرز بسته‌شدن
کندل ممکن است چند ثانیه تأخیر داشته باشد؛ موتور تا دریافت دادهٔ درست صبر می‌کند.
در حالت فعلی، نبود داده برای نماد می‌تواند ارزیابی خروج‌های وابسته به کندل آن
را نیز متوقف کند؛ این سیستم هنوز شبیه‌سازی است و حفاظت واقعی روی صرافی ندارد.

## زمان شروع

تاریخچهٔ ۱۰۰۰ کندلی برای گرم‌شدن اندیکاتورهای تنظیمات فعلی کافی است؛ نیازی
به انتظار ۸۳ روزه برای جمع‌آوری ندارید. کافی‌بودن داده تضمین ایجاد سیگنال نیست.
اولین اسکن با کندل بسته‌شده انجام می‌شود؛ ققنوس سفارش شکست در انتظار می‌سازد و
موج‌سوار ممکن است تأیید کندل‌های بعدی را لازم داشته باشد.

این تغییر فقط مسیر داده و تشخیص کندل بسته را اصلاح می‌کند؛ ریسک و منطق
استراتژی‌ها ثابت‌اند. مصرف‌کنندهٔ قدیمی همچنان کندل آخرِ درحال‌تشکیل را حذف
می‌کند؛ مسیر رسمیِ closed-only آخرین کندل واقعیِ بسته‌شده را حذف نمی‌کند و اندازهٔ
پنجرهٔ اندیکاتور قبلی را حفظ می‌کند.
PnL Paper هنوز شبیه اجرای واقعی صرافی نیست؛ Funding، latency و fill باید
جداگانه بررسی شوند. قطعی سرور، محدودیت API یا تغییر route می‌تواند داده را متوقف کند.
