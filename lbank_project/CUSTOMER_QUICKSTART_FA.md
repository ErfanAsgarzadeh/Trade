# راه‌اندازی نسخه اختصاصی Trade

این نسخه برای شبیه‌سازی و paper trading است؛ سفارش واقعی فیوچرز ثبت نمی‌کند.
سه ربات شاهین، موج‌سوار و ققنوس یک حساب paper مشترک دارند. سایر مشتریان
فایل‌ها و حساب جداگانه دارند. داده demo مصنوعی است و سود آن معیار عملکرد نیست.

## شروع

Docker و Docker Compose v2 را نصب کنید. روی Windows از Docker Desktop
در حالت Linux containers استفاده کنید. در پوشه استخراج‌شده بسته اجرا کنید:

```bash
docker compose up -d --build
docker compose logs --tail=100 bot
```

پورت اختصاصی شما در `.env`، متغیر `DASHBOARD_PORT` است. داشبورد را روی
`http://localhost:PORT` باز کنید. رمز اختصاصی در فایل `secrets/dashboard_pin`
قرار دارد؛ آن را در ویرایشگر محلی بخوانید و در فیلد PIN وارد کنید.
رمز یا فایل بسته را برای دیگران ارسال نکنید. فایل `.env` شامل کلید صرافی نیست.

هر سه ربات ابتدا خاموش‌اند. پس از بررسی سرمایه paper و تنظیمات، از داشبورد
آن‌ها را روشن کنید. روشن‌کردنشان سفارش واقعی ارسال نمی‌کند.

## داده عمومی واقعی و شبیه‌سازی

برای حالت آزمایشی از demo استفاده کنید. برای داده عمومی واقعی، در `.env`
مقدار `PAPER_DATA_MODE=csv-lbank` را قرار دهید و سپس اجرا کنید:

```bash
docker compose --profile market-data up -d --build
```

جمع‌آورنده از زمان آغاز اجرا تاریخچه می‌سازد؛ برای معامله به warm-up کافی
نیاز است. تاریخچه ۴ساعتهٔ موجود را می‌توان داخل `runtime/ohlcv` قرار داد.
ققنوس به بیش از ۵۰۰ کندل قبلی نیاز دارد. داده نمونه‌برداری‌شده، tick نیست
و volume کندل‌های جمع‌آوری‌شده صفر است؛ آزمون نقدشوندگی با آن معتبر نیست.
در نبود تاریخچه کافی، معاملات رد می‌شوند. برای این حالت کلید خصوصی API لازم نیست.

## لایسنس و تمدید

وضعیت و پایان اعتبار در پاسخ `/api/license` پس از احراز هویت و وضعیت حساب
قابل مشاهده است. در انقضا یا نامعتبر بودن لایسنس، ورود و افزودن جدید متوقف
می‌شوند؛ استاپ، خروج، مشاهده حساب و بستن دستی پوزیشن‌ها ادامه دارند.
برای تمدید، فایل `license/license.json` دریافتی از فروشنده را جایگزین کنید.
محتوای لایسنس را ویرایش نکنید. اطلاعات پوزیشن و تنظیمات reset نمی‌شوند.

اگر رمز را عوض کردید، سرویس‌ها را دوباره بسازید تا Docker secret تازه بار شود:

```bash
docker compose up -d --force-recreate
```

## توقف و پشتیبان

```bash
docker compose down
```

این کار دیتابیس را پاک نمی‌کند. برای پشتیبان سازگار، ابتدا سرویس‌ها را متوقف
و سپس پوشه کامل `runtime` را کپی کنید؛ زمان اجرا کپی‌کردن فقط فایل `.db`
می‌تواند WAL و تغییرات جدید را جا بیندازد. نسخه پشتیبان متعلق به همین مشتری است.
پس از بازگردانی، رمز و شناسه مشتری را جابه‌جا نکنید.

داشبورد فقط روی localhost باز است. برای دسترسی از اینترنت باید HTTPS،
پراکسی امن و محدودیت دسترسی توسط مدیر سرور تنظیم شود. پورت را مستقیماً عمومی نکنید.
