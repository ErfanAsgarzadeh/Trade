# لایسنس بر اساس سرمایه و وب‌اپ Trade

پنل مرکزی در `portal_server.py` اکنون یک رابط فارسی راست‌به‌چپ و واکنش‌گرا دارد:
انتخاب سقف سرمایه، دورهٔ یک/سه/شش ماهه، نمایش تخفیف، مرور و ثبت سفارش، لغو درخواست،
تاریخچه، وضعیت اعتبار و دانلود فایل امضاشده. مدیریت اتصال صرافی و وضعیت سه ربات
همچنان در همان پنل است. منبع قیمت فقط سمت سرور، `capital_plans.py`، است.

تمام پلن‌ها شامل یک حساب و هر سه ربات، به‌روزرسانی و پشتیبانی نصب‌اند.
مبالغ در پایگاه داده با سنت صحیح ذخیره می‌شوند. مدت‌ها ماه تقویمی UTC هستند، نه
۳۰/۹۰/۱۸۰ روز؛ پایان ماه بلند به آخرین روز ماه کوتاه محدود می‌شود.

## قواعد سرمایه

- مدیر هنگام فعال‌سازی یا تمدید، شناسهٔ حساب صرافی و اکوییتی دلاری آن را مستقل بررسی می‌کند.
  شناسه از قالب `exchange:uid` استفاده می‌کند و بین کاربران قابل اشتراک نیست.
- سرمایهٔ مبنا برابر سرمایهٔ تأییدشده در شروع دوره به‌اضافهٔ خالص واریز/برداشت‌های
  خارجی تأییدشده است؛ حداقل صفر. سود و زیان معامله، رویداد واریز یا برداشت نیست.
  رشد از سود در همان دوره، ارتقا ایجاد نمی‌کند.
- عبور سرمایهٔ مبنا از سقف، ۷۲ ساعت مهلت ایجاد می‌کند. واریز بعدی این مهلت را عقب
  نمی‌اندازد. پس از مهلت، فقط ورودی‌های جدید، فعال‌سازی سفارش منتظر و افزایش پوزیشن
  متوقف می‌شوند. خروج، استاپ و مدیریت پوزیشن موجود ادامه می‌یابد.
- در ارتقا، دوره و تاریخ انقضای فعلی ثابت می‌مانند. مبلغ برابر اختلاف قیمت دو سقف
  برای همان مدت، ضرب در نسبت زمان باقی‌مانده به کل دوره است؛ به سنت بالاتر گرد می‌شود.
  مبلغ هنگام ثبت سفارش ثابت می‌شود. رشد از سود در ارتقای میان‌دوره نیز هزینه ندارد.
- تمدید پس از انقضا انجام می‌شود؛ اکوییتی جدید دوباره مبنای انتخاب سقف است.
  پیش‌خرید دورهٔ آینده و تغییر حسابِ لایسنس فعال در این نسخه پشتیبانی نمی‌شود.

## اجرای محلی

راهنمای کامل اتصال و استقرار در [PORTAL_FA.md](PORTAL_FA.md) و
[CENTRAL_SERVICE_FA.md](CENTRAL_SERVICE_FA.md) است. در پوشهٔ `lbank_project`:

```bash
python -m pip install -r requirements-portal.txt
python portal_admin.py init
python portal_admin.py create-user alice
export PORTAL_KEY_FILE="$PWD/issuer-keys/portal.key"
export PORTAL_ORIGIN=http://127.0.0.1:8080
export PORTAL_ALLOW_LOCAL_HTTP=1
python portal_server.py
```

در مرورگر `http://127.0.0.1:8080` را باز کنید. اگر پنل قبلاً راه‌اندازی شده است،
دوباره `init` نکنید؛ پایگاه داده در راه‌اندازی عادی به نسخهٔ ۴ مهاجرت می‌کند.
پیش از ارتقای سرویس موجود از پایگاه داده و کلید رمزگذاری جداگانه پشتیبان بگیرید.
Dockerfile پنل و نسخهٔ مستقل هر دو فایل‌های جدید را همراه دارند.

در Chrome/Android گزینهٔ نصب اپلیکیشن یا منوی مرورگر، و در Safari/iOS گزینهٔ
Share → Add to Home Screen قابل استفاده است. خارج از loopback، HTTPS لازم است.
Service Worker فقط صفحهٔ عمومیِ قطع اتصال را ذخیره می‌کند؛ اطلاعات حساب، نشست،
API و لایسنس وارد Cache Storage یا localStorage نمی‌شوند. اپ بدون اینترنت
امکان خرید یا نمایش موجودی به‌روز ندارد.

## تأیید و صدور توسط مدیر

درگاه پرداخت در این نسخه متصل نشده است. ثبت سفارش، برداشت وجه یا فعال‌سازی
خودکار نیست. مشتری سفارش را می‌فرستد؛ مدیر پرداخت، شناسه و سرمایهٔ حساب را
بررسی می‌کند و از محیط مدیریتیِ دارای کلید خصوصی فرمان زیر را اجرا می‌کند.
کلید خصوصی را در کانتینر عمومی پنل یا نصب مشتری قرار ندهید.

اگر هنوز کلید صادرکننده ندارید (فقط یک‌بار):

```bash
python customer_manager.py keygen \
  --private-key issuer-keys/license.private.pem \
  --public-key issuer-keys/license.public.pem
```

همان کلید عمومی باید در نصب مشتری وجود داشته باشد. برای نصب‌های قبلی، از
کلید صادرکنندهٔ خود آن‌ها استفاده کنید؛ کلید جدید جایگزین کلید قبلی نیست.

```bash
python portal_admin.py license-orders
python portal_admin.py approve-license ORDER_ID \
  --private-key issuer-keys/license.private.pem \
  --account-id binance:123456 \
  --equity-usd 10000 \
  --payment-ref RECEIPT_ID
python portal_admin.py export-license alice --output releases/alice-license.json
python customer_manager.py install-license alice \
  --root customers --file releases/alice-license.json
```

`RECEIPT_ID` باید شناسهٔ واقعی و منحصربه‌فرد پرداخت باشد. فرمان تأیید، مبلغ قابل
پرداخت را تغییر نمی‌دهد و پرداخت تکراری یا حساب مشترک بین دو مشتری را رد می‌کند.
فایل خروجی را به همان نصب مشتری منتقل کنید. مشتری نیز از پنل خودش می‌تواند فایل
را دانلود کند. `install-license` امضا، مشتری، سقف و تطابق حساب را بررسی می‌کند و
بدون دست‌زدن به کانفیگ یا پوزیشن‌ها، فایل را اتمیک جایگزین می‌کند. حساب پس از
اولین نصب در `license/account_id` ثابت می‌شود.

اگر نصب مستقل مشتری هنوز ساخته نشده، با دستور `customer_manager.py create`
و همان جفت‌کلید آن را بسازید؛ [MULTI_CUSTOMER_FA.md](MULTI_CUSTOMER_FA.md).
نصب‌های قدیمی باید کد برنامه و Compose جدید را هم دریافت کنند، سپس سرویس‌ها
با `docker compose up -d --build` بازسازی شوند. نسخهٔ جدید Compose مسیر
`BOT_LICENSE_ACCOUNT_ID_FILE=/app/license/account_id` را به پردازش می‌دهد.
در اجرای بدون Docker، `BOT_LICENSE_ACCOUNT_ID_FILE` یا `BOT_LICENSE_ACCOUNT_ID`
را صریح تنظیم کنید. پس از آن تعویض فایل در پوشهٔ mountشده در بررسی بعدی ورودی
خوانده می‌شود و به راه‌اندازی مجدد برای هر تمدید نیاز ندارد.

## ثبت واریز و برداشت خارجی

موجودی لحظه‌ای صرافی به‌تنهایی واریز را از سود تشخیص نمی‌دهد. این نسخه خوراک
تأییدشدهٔ انتقال‌های تمام صرافی‌ها را ندارد؛ مدیر باید صورت‌حساب را بررسی کند:

```bash
python portal_admin.py license-cashflow alice \
  --private-key issuer-keys/license.private.pem \
  --event-id binance:transfer123 \
  --amount-usd 2000
```

برای برداشت، مقدار منفی مانند `--amount-usd=-500` بدهید. شناسهٔ انتقال ثابت و
منحصربه‌فرد برای همان مشتری است؛ اجرای دوبارهٔ همان انتقال مبلغ را تکرار نمی‌کند.
سپس لایسنس جدید را با مسیر جدید خروجی بگیرید و روی نصب مشتری نصب کنید.
**تغییر سرمایه و پایان مهلت فقط پس از نصب فایل به‌روز روی ربات اعمال می‌شوند؛
پنل وضعیت فایل صادرشده را نمایش می‌دهد، نه تأیید نصب یا سلامت اجرای آن.**
خودکارسازی دریافت انتقال‌ها و رساندن فایل به runtime، مرحلهٔ بعدی یکپارچه‌سازی است.

## سازگاری و حدود اجرا

لایسنس‌های قبلی schema=1 بدون تغییر رفتار معتبر می‌مانند. لایسنس‌های سرمایه‌ای
schema=2 علاوه بر مشتری و امضا، به حساب و سقف سرمایه وابسته‌اند. فرمان قدیمی
`renew` نمی‌تواند محدودیت سرمایهٔ schema=2 را حذف کند؛ تمدید از billing انجام می‌شود.
امضاها Ed25519 هستند. این کنترل دسترسی برای توزیع مدیریت‌شده است؛ در مخزن متن‌باز
جایگزین DRM مقاوم به دست‌کاری یا کنترل اجرای سمت سرور نیست.

تغییری در پارامتر استراتژی‌ها یا F داده نشده و سفارش واقعی فعال نشده است.
موتور فعلی همچنان paper است. کنترل سرمایهٔ paper بر پایهٔ seed ثابت و رویدادهای
امضاشده انجام می‌شود؛ این پنل ابزار مدیریت سرمایه یا اجرای واقعی صرافی نیست.

```bash
PYTHONPATH=. python -m pytest tests/test_capital_licensing.py \
  tests/test_customer_distribution.py tests/test_portal.py \
  tests/test_portal_queue.py tests/test_multi_exchange.py -q
node tests/test_portal_ui.cjs
```

تست مرورگر اختیاری با Playwright و Chromium:

```bash
python -m pip install playwright==1.62.0
python -m playwright install chromium
PORTAL_TEST_PLAYWRIGHT_BROWSER=1 PYTHONPATH=. \
  python -m pytest tests/test_portal_browser.py -q
```

یا `PORTAL_TEST_CHROMIUM=/path/to/chromium` بدهید. متغیر `PORTAL_SCREENSHOTS`
مسیر ذخیرهٔ تصاویر تست را مشخص می‌کند. تست با حساب، پرداخت و کلید موقتی کار می‌کند؛
هیچ ارتباطی با حساب صرافی یا پرداخت واقعی ندارد.
